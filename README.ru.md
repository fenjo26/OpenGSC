## Почему OpenGSC

Сервисы вроде seogets.com просят **$19–$79/месяц** за визуализацию данных Google Search Console, которыми вы уже владеете. OpenGSC дает вам ту же ключевую аналитику — клики, показы, CTR, позиции, ключевые слова Striking Distance (на пороге топ-10), угасание контента (Content Decay) и каннибализацию — по цене VPS за $5/месяц, потому что это *и есть* ваш VPS: один скрипт установки, собственная база данных SQLite, собственный домен и собственное OAuth-приложение Google. Данные вашей Search Console никогда не проходят через сторонние серверы.

Помимо дашборда, OpenGSC содержит две вещи, которых нет в большинстве инструментов GSC: полноценный **пакет ИИ-инструментов для генерации контента** (`/seo-tools` — анализ конкурентов, генерация структуры на основе сущностей, написание статей целиком, GEO/AI-search аудит цитирования, отслеживание тональности упоминаний бренда) и **приватную сеть индексации** (`/indexer` — ваша собственная инфраструктура сайтов-дорвеев с клоакингом и верификацией ботов для быстрого и бесплатного индексирования).

|---|---|---|
| Цена | Бесплатно навсегда | $19–$79/месяц |
| Хостинг | Ваш собственный VPS | Их облако |

| Сайты / Google аккаунты | Безлимитно | Ограничено тарифом |
| ИИ SEO-пакет контента | ✓ Включен, ваш API-ключ | Редко доступен |
| Приватная сеть индексации | ✓ Включена | Не предлагается |

**Честные компромиссы:** вам нужен VPS и домен (Google OAuth не работает на чистом IP-адресе), обновления вы ставите сами (`git pull && npm run build && pm2 restart`), и в системе нет встроенного разделения на команды или white-label. Если это приемлемый компромисс ради контроля над своими данными и отсутствия подписок — читайте дальше.

## ✨ Возможности

### Объединенный дашборд GSC

- **Один дашборд, все аккаунты** — любой сайт из любого подключенного Google-аккаунта на одном экране с графиком спарклайнов трафика для каждого ресурса.
- **Портфельные дашборды Google · Bing · Яндекс** — переключение всего дашборда между поисковиками в один клик. Google читается из локальной базы; **Bing** и **Яндекс** тянутся вживую из их Webmaster API по всем подключённым аккаунтам и показывают *их собственные* верифицированные сайты (а не только список Google), те же KPI-карточки, карточки сайтов со спарклайнами, сортировки, поиск, теги и CSV. Живые данные движков кэшируются на сервере — вкладка открывается мгновенно после первой сборки; кнопка **Sync** обновляет все три поисковика разом.
- **Быстрые периоды** — кнопки 7д / 28д / 3м / 6м / 12м / 16м, а также сравнение с предыдущим периодом, год к году или полностью кастомные диапазоны.
- **Интерактивные переключатели** — клики, показы, CTR и средняя позиция, с мгновенно пересчитываемой суммарной статистикой по всей сетке сайтов при фильтрации по тегам.
- **Быстрая ручная проверка индексации** — бейдж рядом с каждым сайтом открывает поиск `site:domain.com` в новой вкладке и следует активной вкладке движка (**G** → Google, **b** → Bing, **Я** → Яндекс).
- **Теги, избранное, сортировка и скрытие** — управляйте сотнями сайтов, закрепляйте важные проекты и скрывайте неактивные.
- **Режим приватности (Blur)** — в один клик размывает названия аккаунтов, email, домены и метрики для безопасного шаринга экрана или создания скриншотов.
- **Бейджи Ahrefs DR** — карточки сайтов показывают Domain Rating домена, подгружаемый через бесплатный публичный эндпоинт Ahrefs и кэшируемый на 7 дней. *Domain Rating предоставлен [Ahrefs](https://ahrefs.com/).*

### Портфельная SEO-аналитика

Выносите общую SEO-аналитику на главный дашборд OpenGSC:
- **Striking Distance** — ключевые слова из топ-20 на пороге топ-10 по всей сетке сайтов.
- **Каннибализация** — список страниц, конкурирующих за одни и те же запросы, по всей базе доменов.
- **Content Decay** — сводная тепловая карта угасания страниц по всем сайтам для предотвращения просадок трафика.

### Детальная статистика сайта

Каждый домен имеет свою страницу детального анализа с трендами кликов/показов/CTR/позиций и специальными отчетами:
- **Striking Distance Keywords** — запросы на позициях 4–20 с хорошим объемом показов: ваши точки быстрого роста.
- **Keyword Cannibalization** — запросы, по которым конкурируют несколько ваших страниц, с разбивкой на лидера и аутсайдеров.
- **Content Decay Map** — тепловая карта страниц, теряющих клики за последние месяцы.
- **CTR Benchmark** — сравнение реального CTR страниц со стандартными кривыми распределения кликов для поиска страниц с плохим сниппетом.

### Интеграция с Google Analytics 4 и Microsoft Clarity

Связывайте ресурсы GA4 (сессии, вовлеченность, ключевые события, доход) и проекты Microsoft Clarity (записи сессий / тепловые карты за 30 дней) в рамках детальной страницы сайта. Инструкция по настройке: [`docs/GA4-SETUP.md`](docs/GA4-SETUP.md).

### Rank Tracker

Отслеживайте позиции ключевых слов (с привязкой к стране/языку/устройству) через Serper, DataForSEO или ScrapingRobot на одном графике с реальными данными GSC.

### AEO Tracker — видимость в поисковых ИИ-ассистентах

"Answer Engine Optimization": проверяет, **цитируется ли ваш сайт при ответах ИИ-ассистентов** — ChatGPT и Perplexity (через веб-поиск), Claude и Grok (через упоминания бренда), формируя историю упоминаний.

Под ним — **второй источник** с другой задачей. Трекер задаёт *ваши* вопросы вживую на *ваших* ключах сегодня; **Видимость бренда** читает индекс DataForSEO по тому, что модели действительно отвечали — включая вопросы, которые вы и не думали отслеживать. Он показывает, как часто всплывает бренд, в каких вопросах, какие ваши страницы цитируют чаще, и **долю голоса против девяти конкурентов** — число, которое живой трекер получить не может в принципе, потому что он всегда спрашивает только от вашего имени. Поиск по домену находит ответы, которые на вас сослались; поиск по названию — те, где вас назвали без ссылки. Индекс покрывает ChatGPT и Google AI Overview и обновляется примерно раз в месяц, поэтому две панели стоят рядом и подписаны, а не слиты в одну: ноль здесь не доказывает, что вас не видит Claude.

### Проверка бэклинков

База обратных ссылок на сайт с проверкой их доступности (живая / мёртвая / заблокирована) и статуса индексации в Google через XML River. Проверка живости ретраит временные сбои (5xx, лимиты запросов, обрывы сети) и отличает действительно мёртвую ссылку от той, которую отклонил WAF/бот-защита — так 403 от Cloudflare больше не читается как мёртвый бэклинк.

### Веса ключей, ссылочный профиль и конкуренты

Search Console показывает, как выступаете вы. Он не знает, сколько там вообще спроса, насколько тяжело выиграть ключ и кто выигрывает вместо вас. Модуль подтягивает данные Ahrefs/Semrush и — что важнее — накладывает их на ваши данные GSC: ценность именно в пересечении, потому что у каждого источника есть только своя половина.

- **Веса ключей** в Striking Distance и Rank Tracker — частотность, KD, CPC и колонка **Потенциал**: сколько ключ мог бы приносить в топе первой страницы за вычетом того, что приносит сейчас. Показы — это спрос, отфильтрованный вашей текущей видимостью; частотность — сам рынок.
- **Конкуренты** — подтягиваете ключи конкурента, и пересечение с вашим GSC делит каждую строку на три вывода: *в досягаемости* (вы в топ-30 — дорабатывать страницу, URL тут же), *не та страница* (показы есть, но ничего не выигрывает — мимо интента), *нет контента* (писать).
- **Ссылочный профиль** — ссылающиеся домены, живые и потерянные, с историей и алертом о пропаже. Стоит рядом с ручным списком бэклинков, который отвечает на другой вопрос: дожила ли ссылка, которую поставили *вы*.
- **Проверка спроса в Content Decay** — клики упали при ровном спросе, это позиции; упали вместе со спросом — это рынок, и рерайт тут не поможет.
- **Здоровье домена в Indexer** — DR и ссылающиеся домены по каждому домену сетки, до того как строить на сожжённом дропе.

**Ключ API не обязателен.** Выгрузка CSV из Ahrefs или Semrush наполняет ровно тот же кэш, что и API (`SEO Tools → Импорт метрик`) — тип отчёта определяется по заголовкам колонок. Если у вас браузерная подписка, экспорт уже оплачен; API нужен для того, что должно обновляться без человека.

Если ключ всё-таки используется: каждая кнопка показывает цену до нажатия, KD вынесен в галочку (он примерно удваивает стоимость ключа), месячный лимит юнитов проверяется на сервере. При загрузке страницы ничего не запрашивается никогда.

Настройка и расчёт стоимости: **[docs/METRICS-SETUP.md](docs/METRICS-SETUP.md)**.

### Спрос — подбор ключей и разбор домена

Все остальные экраны OpenGSC начинаются с запросов, по которым вы уже показываетесь. **Спрос** начинается с рынка — и это единственное место, которое может вернуть ключ, о котором Search Console никогда не слышал. Работает на ключе DataForSEO, который у вас, возможно, уже настроен для SERP: ни нового провайдера, ни новой подписки.

- **По ключу** — исходная фраза уходит в DataForSEO Labs и возвращается тем, что люди действительно ищут: частотность, сложность, CPC, интент и спарклайн тренда за 12 месяцев. Дальше каждая строка получает ответ от *вашего* GSC: **в досягаемости** (топ-30 — дорабатывать страницу, URL в строке), **не та страница** (показы есть, ничего не выигрывает — мимо интента), **нет контента** (писать). Ahrefs знает первую половину каждой строки, Search Console — вторую; обе половины сходятся только здесь.
- **По домену** — вводите любой домен и получаете оценку органического трафика, число ключей, их распределение по позициям, термины, которые реально приносят трафик, и страницы, на которых он держится. Работает с чужими доменами: конкурент, клиент до онбординга, дроп, который вы присматриваете. Свой сайт можно указать — тогда добавится колонка сравнения, но это не обязательно.
- **Три режима поиска, один платный вызов.** `related` ищет семантических соседей, `suggestions` — длинный хвост с вашей фразой внутри, `ideas` — то же по смыслу другими словами. **Авто** проходит их по порядку и останавливается на первом, который дал достаточно терминов: не объединяет все три, потому что каждый — отдельный счёт, а пересечение между ними в основном дубли.
- **Всё кэшируется, цена известна заранее.** Поиски хранятся 14 дней, разборы доменов — 7, поэтому возврат к уже оплаченному вопросу ничего не стоит. Каждая кнопка показывает цену до нажатия, уточнённые «clickstream»-объёмы вынесены в галочку, которая честно пишет про удвоение стоимости, месячный лимит проверяется на сервере.
- **Найденные ключи попадают в общий кэш метрик**, так что веса появляются в Striking Distance и Rank Tracker бесплатно — за один и тот же объём никто не платит дважды.
- **Агенты тоже это умеют**: `get_keyword_demand` (бесплатный, читает уже исследованное) и `research_keywords` (платный, за гейтом `confirm: true`), плюс готовый скилл `keyword-research` в [`.agents/skills/`](.agents/skills/).

Без ключа DataForSEO вкладка всё равно открывается и показывает то, что уже сохранено — тот же принцип «ничего не обязательно», что и во всём остальном приложении.

### Проверка здоровья сайта

Панель, объединяющая аудит SSL-сертификата (срок действия, эмитент), проверку на вирусы/фишинг через **Google Safe Browsing** и **VirusTotal**, а также показатели скорости **Core Web Vitals** через PageSpeed Insights API.

### Интеграция с Bing, Яндекс.Вебмастером и IndexNow

- **Переключатель поисковиков на дашборде сайта** — рядом с данными GSC переключаетесь на полноценные живые дашборды Bing (клики, показы, CTR, средняя позиция, график, топ запросов и страниц, страницы в индексе, ошибки обхода) и Яндекса (ИКС, страницы в поиске/исключено, график, топ запросов с позициями, диагностика сайта от самого Яндекса). Кнопка Sync обновляет все подключённые поисковики разом. Инструкция по получению ключей и токенов: [docs/SEARCH-ENGINES-SETUP.md](docs/SEARCH-ENGINES-SETUP.md).
- **Отправка Sitemap** в Bing (API или ping) и Яндекс.Вебмастер в один клик из вкладки Indexing.
- **Переобход URL в Яндексе** — отправка страниц на переиндексацию с учётом дневной квоты, через ваш собственный OAuth-токен.
- **Моментальный пуш URL через IndexNow** — отправка новых и измененных адресов напрямую в поисковые системы (Bing, Yandex) для мгновенного обхода.

### Технический аудит сайта — встроенный краулер

Бесплатный технический аудит без внешних API: OpenGSC сканирует ваш сайт прямо с вашего VPS (до 500 страниц) и сообщает о битых внутренних ссылках, отсутствующих или дублирующихся заголовках title, отсутствующих meta descriptions, проблемах с H1, страницах с `noindex`, несовпадениях канонических адресов, тонком контенте, изображениях без alt-тегов, медленных ответах и клиентских (JS-рендеренных) страницах, где статическим HTML-сигналам доверять нельзя. Всё это сводится в оценку здоровья с фильтруемой таблицей. Каждый аудит также запускает проверку **доступности для AI**: не заблокированы ли AI-краулеры (GPTBot, ClaudeBot, PerplexityBot, OAI-SearchBot, Google-Extended, CCBot, Bytespider) в вашем `robots.txt` и есть ли `/llms.txt` — корневой `Disallow` для GPTBot это тихая причина, по которой ответный движок вас никогда не цитирует, и здесь она показана как чинимый диагноз, а не только как симптом. Результаты хранятся как история аудита и экспортируются в Markdown.

### Уведомления и дайджесты в Telegram и Slack

Подключите собственного бота Telegram (настройка через @BotFather за 1 минуту, токен вставляется в **Настройки → Уведомления**) и/или Slack Incoming Webhook — OpenGSC будет присылать отчеты прямо в чат:
- **Алерты** (проверяются каждый час): падение отслеживаемого ключа на N+ позиций, просадка кликов на X% за неделю, скорое истечение SSL-сертификата, низкий балл аудита сайта.
- **Дайджесты** (вкладка **Дайджест**): портфельный отчёт по всем сайтам *или по одному тегу* (например, сетке PBN). Вид **на экране — полный и подробный** (явный диапазон дат, KPI портфеля, сильнее всего выросшие/просевшие сайты, растущие/падающие запросы, *все* запросы на пороге топ-10, сайты, требующие внимания, движения позиций — каждая секция с «показать все» и CSV), а **в Telegram уходит короткая выжимка** (безопасно для лимита в 4 000 символов). **Вкладки Google / Bing / Яндекс** разбивают отчёт по поисковикам (вкладки движков переиспользуют кэш портфеля). Опциональный **AI-вывод** (на вашем AI-ключе) пишется сверху и **включён по умолчанию, если задан хоть один AI-ключ**. Предпросмотр на экране, отправка по кнопке или расписание.

### Гостевые дашборды — read-only ссылки для клиентов

Поделитесь дашбордом сайта с клиентом без создания аккаунта: **сайт → Настройки → Публичная ссылка** генерирует токенизированный read-only URL. Гость видит аналитику только этого сайта (дашборд, позиции, GA4, здоровье, аудит) — без настроек и кнопок действий; ссылку можно перевыпустить или отозвать в любой момент.

### MCP-сервер — подключение ИИ-агентов

В OpenGSC встроен **MCP-сервер** на `/api/mcp` с **40 инструментами**. Любой MCP-совместимый ИИ-клиент (Claude Code, Claude Desktop, Cursor, Codex) получает доступ к данным о ваших сайтах, эффективности поиска, ключевых словах Striking Distance, каннибализации, угасании контента, CTR-бенчмарку, группам контента, позициям и их истории, AEO-видимости, GEO-аудитам, бэклинкам, спросу и сложности ключей, разрывам с конкурентами, здоровью сайта, индексации, техническому аудиту, GA4, Clarity, портфелям Bing и Яндекса, сети индексации, сработавшим алертам, дайджестам и истории генераций — а также может выполнять произвольные read-only SQL-запросы. Сгенерируйте токен в **Настройки → API и MCP**, затем подключите:

```bash
claude mcp add --transport http opengsc https://your-domain.com/api/mcp \
  --header "Authorization: Bearer <token>"
```

Агент может не только читать данные, но и **оптимизировать страницы**. `get_optimization_brief` одним вызовом отдаёт всё, что известно про один URL: его запросы, ключи на пороге топ-10, разрыв по CTR, динамику за полгода, конфликты каннибализации, находки техаудита и текущий текст страницы. Новую версию агент пишет сам, а `analyze_text` проверяет её детерминированно — уникальность, сохранность структуры заголовков и любое число или название, которого в исходнике не было. Модель для этой проверки не вызывается: она ничего не стоит и всегда даёт один и тот же ответ.

У каждого инструмента указано, во что обходится его вызов, и `get_capabilities` возвращает эту разбивку: **local** (читает вашу базу — бесплатно и мгновенно, 32 из 40), **quota** (обращается к Google по вашему OAuth), **net** (загружает страницу) и **paid** (тратит ваши кредиты). Трём платным инструментам — встроенному рерайтеру, полному пайплайну статьи и подбору ключевых слов — обязателен явный `confirm: true`, поэтому агент, изучающий список инструментов, не может списать с вас деньги случайно. Два первых асинхронные: возвращают id задачи и сохраняют каждую готовую страницу сразу, поэтому обрыв связи или перезапуск сервера не выбросят работу, за которую вы уже заплатили. Подбор ключевых слов синхронный, потому что ему это не нужно: результат попадает в кэш до возврата ответа, и брошенный вызов всё равно оставляет поиск, который потом повторяется бесплатно.

Подробная инструкция: [`docs/MCP-SETUP.md`](docs/MCP-SETUP.md).

## 🧠 ИИ SEO-пакет инструментов (`/seo-tools`)

Полноценный конвейер от анализа конкурентов до публикации готовых статей. Все модули опциональны и используют ваши собственные API-ключи (Anthropic, OpenAI, Gemini, OpenRouter, Kimi/Moonshot, kie.ai и др.) по себестоимости.

- **Кластеризация ключевых слов**: группировка семантики по схожести выдачи (SERP overlap) на основе реального топ-10 Google.
- **Генератор структуры (Outline)**: парсинг конкурентов по запросу, определение их интента и сущностей, автоматическое построение ТЗ для автора с защитой от ИИ-галлюцинаций (Fact-scrub) и поддержкой Casino RAG для гемблинг-тематик.
- **Генератор текста**: пошаговое написание статьи частями (что сохраняет качество прозы на больших объемах) с контролем объема (Volume guard) и поддержкой линковки на источники. Опционально (по умолчанию выключено, поведение существующих запусков не меняется): поле **температуры** — с предупреждением выше 1.2 и красной отметкой на 1.5, где текст вырождается в бессмыслицу — и тумблер **запрета маркеров**, подставляющий лексику из вашей модели ИИ-отпечатка как запрещённые слова. Поскольку чанки — отдельные вызовы модели, температура сдвигается по чанкам на небольшую детерминированную величину, и готовая статья перестаёт быть продуктом одного равномерного сэмплирования. На шаге структуры температура ограничена потолком 0.8, а ретрай при непарсящемся ответе уходит на 0: аутлайн обязан вернуть валидный JSON, а рандомность сэмплирования ломает именно это.

- **Лаборатория ИИ-отпечатка (AI-Fingerprint Lab)**: статистические ИИ-детекторы не смотрят на стиль — они оценивают **распределение частот токенов по окнам ~300 слов**. Сигнал воспроизводим локально, поэтому инструмент обучает bag-of-words классификатор **на ваших же двух корпусах**: страницы конкурентов из выдачи как человеческий эталон, ваша собственная История генераций как машинный. Никаких сторонних детекторов, подписок и отправки текста наружу. Чистый TypeScript, ноль зависимостей, работает в любом алфавите.

  Три вкладки. **Анализ** — оценка текста или сохранённой статьи: средний скор, **heatmap по окнам** (среднее прячет текст, наполовину чистый и наполовину очевидный), **словарь маркеров**, реально сдвинувших оценку, и человеческая лексика, которой у вас нет. Кнопка **«Хуманизировать»** переписывает текст с запретом этих маркеров, скорит три варианта и показывает дельту «было → стало». **Корпус** — сбор эталона по ключу или списку URL, обучение, несколько именованных моделей; модель привязана к нише и языку, поэтому на каждую нишу своя, а показатель **разделения** на отложенной выборке честно сообщает, если модель слабая. **Стенд** — один промпт на разных ваших моделях и температурах со сравнением результатов: выбор модели перевешивает любые ухищрения с промптом, а опубликованные сравнения моделей устаревают за месяцы, поэтому мерить нужно те модели, ключи от которых есть у вас.

  Скор — наименее интересный выход. Главное — **список маркеров**: его экспорт запрещает эту лексику на этапе генерации, где список слов реально что-то меняет. Переписывание готового текста статистический детектор почти не сдвигает — и инструмент говорит об этом прямо, по факту слабого результата, а не постоянным дисклеймером.

  Два предохранителя, потому что эта лексика уходит прямо в промпт. Слова, которые встречаются у **40%+ страниц конкурентов**, считаются терминологией ниши и не предлагаются никогда: запрет терминов, которыми пользуется вся ниша, не делает текст человечнее — он заставляет модель обходить слова, нужные статье. И весь список **можно просмотреть до применения**: клик по слову оставляет его разрешённым, и это решение переживает переобучение модели.

- **Рерайт контента (Content Rewriter)**: вставьте текст или **URL** (парсится автоматически) → получите **N уникальных вариантов** (1–5) с сохранением смысла, фактов, чисел и ссылок. У каждого варианта — **% уникальности** (сходство по триграммам слов), число слов и, если обучена модель отпечатка, **ИИ-оценка**; копирование/скачивание. Опции: язык, тон, температура и тумблер **запрета маркеров**. Тумблер **«маскировать AI-паттерны»** убирает машинные тики (тире, «furthermore», «важно отметить»…) — честно позиционирован как читаемость для редактора, а не антидетект: подмена фраз в готовом тексте статистический детектор не двигает.

  Каждый вариант проверяется на **дрейф фактов** — детерминированный диф чисел, сумм, процентов и названий-идентификаторов (RTP, MegaWays, iPhone) между исходником и рерайтом. Значения, которые **появились**, но которых не было в исходнике, помечаются красным (именно выдуманная цифра уходит в публикацию); **пропавшие** — жёлтым. Валюты канонизируются, поэтому `$50`, `50 USD` и `50 долларов` — одна сумма, а локальные разделители разрядов никогда не дают ложную тревогу. Без вызова модели и без затрат. Проверяются значения, а не утверждения — и это сказано прямо в панели.

  Работает на ваших мульти-провайдерных ключах. Встроен в **Content Decay**: у каждой проседающей страницы — кнопка «Рерайт» с уже подставленным URL. Незаменим для больших аффилиат-сеток, где дубли контента — реальный риск.
- **Googlebot View — детектор клоакинга и PBN**: «увидеть» страницу глазами краулера Google и поймать то, что скрыто от обычного визита. Тянет URL несколькими **User-Agent** (Googlebot mobile/desktop, браузер, опц. Googlebot + `Referer` из выдачи), вручную проходит **цепочку редиректов** и **сравнивает** ответы — вердикт *чисто / подозрительно / клоакинг*, таблица различий (финальный статус/URL, canonical, meta robots, hreflang, JS-редиректы, индексируемость). Для **своих** сайтов в GSC добавляет **True Google View** — реальный вердикт Google через URL Inspection API. Спека: [docs/GOOGLEBOT-VIEW-SPEC.md](docs/GOOGLEBOT-VIEW-SPEC.md).
- **Анализ упущенного контента (Content Gap)**: сравнение вашей страницы с конкурентами в топ-10 и точные рекомендации, чего не хватает на вашем URL.
- **Landing Page Builder**: составление ТЗ, прототипов и текстов для коммерческих страниц. Поддерживает импорт структуры ваших страниц, в том числе по скриншоту.
- **GEO-аудит (Generative Engine Optimization)**: анализ того, как ИИ-поисковики (ChatGPT, Perplexity) цитируют бренды по вашим целевым запросам, и рекомендации по улучшению видимости в ИИ.
- **Трекер упоминаний и тональности**: отслеживание бренда в сети с определением тональности и эмоций через DataForSEO.
- **Мониторинг ссылок (Link Monitor)**: отслеживание свежих качественных ссылок конкурентов через API Ahrefs v3 и поиск сайтов, которые ссылаются сразу на нескольких конкурентов (лучшие доноры для аутрича).
- **Редакционная политика**: создание и применение единых правил стиля, тона и стоп-слов для всех генерируемых текстов. Лаборатория ИИ-отпечатка умеет отправлять свой словарь маркеров прямо в список запрещённых слов политики. Чего в этих промптах намеренно **нет** — указаний о том, *как* писать («пиши естественно», «варьируй длину предложений», «избегай ИИ-клише»). По A/B-тестам такие формулировки дают обратный эффект: модель применяет их как формальные правила, распределение сужается, и текст читается ещё более машинным. Конкретный список слов такого эффекта не даёт — поэтому механизмом здесь выбран именно он.
- **История**: единый серверный лог всех генераций с возможностью возобновления зависших задач. При активной модели ИИ-отпечатка у каждой сохранённой статьи прямо в списке стоит её **ИИ-оценка** — видно, какие генерации читаются машинными, не открывая их.

## 🕸️ Приватная сеть индексации (`/indexer`)

Инструмент управления сетью сайтов-дорвеев для быстрого индексирования целевых страниц.
- **Управление доменами**: создание шаблонов контента (Ecommerce, Блог и др.), настройка редиректов и уникальных ключей.
- **Планировщик перелинковки**: визуальный построитель топологий связей доменов (кольцо, сеть, пирамида) с экспортом HTML-кода.
- **Клоакинг бота**: проверка посетителей по User-Agent и двойному DNS-запросу (PTR-запись). Боты поисковых систем (Google, Yandex, Bing) видят контент дорвея и ссылки для индексации, а обычные пользователи и краулеры-шпионы перенаправляются на целевой сайт.
- Deployed-скрипты доступны в четырех вариантах: Nginx-конфиг, Astro middleware, PHP-дорвей или статический PHP-враппер. Подробно в [`docs/INDEXER-SETUP.md`](docs/INDEXER-SETUP.md).

## 🚀 Установка

Подробный шаг за шагом гайд по настройке Google Cloud Console и запуску скрипта установки описан в английской версии [README.md](README.md#-installation). 

Краткий вариант установки на чистый сервер:
```bash
curl -fsSL https://raw.githubusercontent.com/fenjo26/opengsc/main/install.sh | sudo bash
```
Скрипт спросит домен, установит Node.js 24 LTS, PM2, Nginx, выпустит SSL Let's Encrypt, настроит файрвол и запустит приложение.

Для обновления версии достаточно выполнить:
```bash
cd /root/opengsc
git pull
npm install
npx prisma db push
npm run build
pm2 restart opengsc
```

Полная документация по архитектуре, GA4, Docker, MCP и индексатору доступна в папке [docs/](docs/).
