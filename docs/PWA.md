# PWA и web push (N10)

OpenGSC устанавливается на телефон как приложение и получает push-уведомления о событиях
(алерты, лидах, аптайме, дайджестах) без Telegram — через канал **Web Push**. В офлайне
показываются последние данные дашборда.

## Что нужно BEFORE start: HTTPS

Service worker и Push API работают **только на `https://`** (и на `localhost`).
На `http://` интерфейс не показывает кнопку подписки, а объясняет причину
(Настройки → Push-уведомления → «Push работает только по HTTPS»).

На **iOS** (16.4+) web push доступен только PWA, установленному на экран «Домой»:
Safari → «Поделиться» → «На экран Домой», после открытия из иконки — подписка в Настройках.
На Android и в настольных Chrome/Edge подписка работает прямо с сайта.

## Установка

- **Android / Chrome / Edge**: на дашборде или в Настройках появится кнопка
  «Установить приложение» (событие `beforeinstallprompt`).
- **iPhone / iPad**: кнопки не будет — iOS не отдаёт `beforeinstallprompt`; следуйте
  инструкции «Поделиться → На экран Домой» в карточке настроек push.

Манифест: `public/manifest.webmanifest` (`display: standalone`, иконки 192/512 + maskable
в `public/icons/`). Service worker: `public/sw.js`.

## Включение push

Настройки → «Push-уведомления»:

1. «Включить на этом устройстве» — браузер спросит разрешение, подпишет устройство
   (строка в таблице `PushSubscription`) и начнёт присылать уведомления.
2. Каждое устройство имеет свой фильтр событий (пусто = все): алерты, дайджест, аптайм,
   индексация, упоминания, лиды, local pack, тренды. Это телефон конкретного человека —
   подписки владельца и всех принятых участников workspace получают уведомления независимо.
3. «Отправить тест» — проверка доставки на все устройства workspace.
4. «Выключить на этом устройстве» или удаление строки устройства в списке.

Уведомление открывает связанный экран: алерт сайта — страницу сайта, лид — `/leads`,
остальное — дашборд.

## VAPID-ключи

Ключи генерируются при первом запросе и хранятся в `InstanceSetting`
(`vapid_public`, `vapid_private`). Приватный ключ никогда не уходит в браузер.

Переопределение окружением (например, общие ключи для нескольких инстансов):

```
OPENGSC_VAPID_PUBLIC_KEY=<urlsafe base64>
OPENGSC_VAPID_PRIVATE_KEY=<urlsafe base64>
OPENGSC_VAPID_SUBJECT=mailto:you@example.com
```

Env побеждает хранилище; полунастроенный env (один из двух ключей) игнорируется целиком.
Сгенерировать пару отдельно: `npx web-push generate-vapid-keys`.

## Поведение доставки

- `web-push.sendNotification` с `TTL: 3600` (час).
- Push-сервис ответил **404/410** — подписка удалена немедленно (устройство отписалось).
- Другая ошибка — счётчик `failures`; после **5 подряд** подписка удаляется
  (приложение удалено / данные браузера стёрты).
- Успех сбрасывает счётчик и пишет `lastOkAt` — «последняя удачная доставка» в UI.
- `body` уведомления — плоский текст без markdown, ≤ 240 символов.

Кнопка «Push на устройства» в карточке каналов уведомлений показывает число устройств и
ссылается на карточку push-настроек.

## Офлайн-чтение

`public/sw.js` кэширует:

- HTML — network-first, офлайн отдаётся последняя загруженная копия;
- `/_next/static/**` — stale-while-revalidate;
- из API — **только** `GET /api/uptime/status` и `GET /api/gsc/sites` (сводка дашборда).
  Когда сеть недоступна и отдаётся кэш, внизу экрана появляется плашка
  «Нет сети — данные от {время}». Все остальные запросы API никогда не кэшируются.

## Ручная проверка (чек-лист)

1. `https://…/manifest.webmanifest` открывается как JSON; `https://…/sw.js` отдаёт файл.
2. DevTools → Application → Manifest: иконки 192/512 + maskable, без предупреждений.
3. Настройки → Push: на http:// — объяснение, кнопок нет; на https:// — «Включить».
4. После подписки: «Отправить тест» → уведомление с заголовком OpenGSC.
5. Клик по уведомлению открывает связанный экран.
6. DevTools → Network → Offline → перезагрузка дашборда: плашка «данные от …».
7. Network → Online: плашка исчезает.

## Маршруты

| Метод и путь | Право | Что делает |
|---|---|---|
| `GET /api/push/vapid` | read | публичный VAPID-ключ |
| `GET /api/push/subscribe` | read | мои устройства |
| `POST /api/push/subscribe` | act | подписать устройство (upsert по endpoint) |
| `PATCH /api/push/subscribe` | act | фильтр событий устройства |
| `DELETE /api/push/subscribe` | act | удалить подписку |
| `POST /api/push/test` | act | тестовая доставка на все устройства workspace |

Инстанс без `prisma db push` отвечает `{ notMigrated: true }`, UI показывает подсказку.
