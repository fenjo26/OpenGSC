## Что делает эта задача

### 1. Фетчер — `src/lib/drops/glue/fetchPages.ts` (новый)

```ts
export interface FetchOptions {
  ua: "browser" | "googlebot";
  timeoutMs?: number;   // по умолчанию 8000
  maxBytes?: number;    // по умолчанию 1_000_000
}
export async function fetchClusterPages(urls: string[], opts: FetchOptions): Promise<PageFetch[]>;
```

- Через существующий `safeFetch`. **SSRF-guard не ослаблять** — URL приходят из формы.
- Редиректы ведём вручную (`redirect: "manual"`), максимум 5 прыжков, каждый пишем в `redirectChain`; аннотации читаются с финального ответа.
- Не больше 10 URL за вызов, параллельность 4, один и тот же хост — последовательно.
- `ua: "googlebot"` подставляет UA гуглбота. Смысл: половина таких связок отдаёт блок аннотаций только боту. Запрос двумя UA и диф отчётов — отдельная кнопка «сравнить с тем, что видит бот»; расхождение в canonical/alternate показываем как находку `cloaked_annotations` (severity `warn`).
- Тело обрезаем по `maxBytes`; `<head>` всегда влезает, а 40-мегабайтные дорвеи встречаются.

### 2. API — `src/app/api/drops/glue/route.ts` (новый)

| Метод | Тело | Ответ |
|---|---|---|
| `POST ?action=plan` | `GlueSpec` | `GluePlan` — без сети, мгновенно |
| `POST ?action=check` | `{ mode, urls: string[], plan?: GluePlan, ua? }` | `{ report: GlueReport, facts: PageFacts[] }` |

Валидация входа zod'ом как в соседних роутах `/api/drops/*`. `action=check` — owner-only, как остальные сетевые ручки модуля.

### 3. UI — карточка «Склейка» внутри `/drops?tab=activation`

- Форма: URL дропа, строки «локаль + URL мани-страницы» (добавить/убрать), режим `cluster | funnel`, необязательный `x-default`.
- Правки `checkLocale` показываем сразу под полем локали (`locale_fixed` — жёлтым, `locale_invalid` — красным), не дожидаясь отправки.
- Результат: по одной вкладке на страницу, `<html lang="…">` отдельной строкой + блок `<head>` с кнопкой «копировать». Копируется ровно то, что поедет в разметку.
- Кнопка «Проверить вживую» шлёт `action=check` с тем же планом. Находки — списком, сгруппированные по странице, `blocker` красным, `warn` жёлтым, `info` серым. `ok: true` — зелёная плашка.
- Строка риска, постоянно видимая в режиме `funnel`, а не в тултипе:
  > Канoникал мани-домена ведёт наружу: пока Google верит кластеру, сигналы сливаются в дроп, но владелец дропа управляет вашими позициями, и обратно это разбирается только с потерей выдачи.
- Кнопка «Заполнить из кандидата» — если карточка открыта из строки таблицы `/drops`, домен кандидата подставляется как дроп.

### 4. i18n

~22 ключа с префиксом `dropsGlue*` **во все 7 локалей** (`en ru uk fr es de zh`) — одной задачей, иначе `check:i18n` красный. Коды находок переводятся ключами `dropsGlueFinding_<code>`; список кодов — из `validate.ts`, они же в `KNOWN_GLUE_FINDINGS` (экспортировать массивом, чтобы тест проверял совпадение ключей и кодов, как это сделано для `serpmonProblem_*`).

В `package.json` дописать в **конец** строки `test:unit` неэкранированный глоб `src/lib/drops/glue/*.test.ts`. Порядок существующих записей не менять.
