# CONTRACT — волна «AI Readiness» (T1…T3 + скор)

Один исполнитель, коммиты прямо в `main`, пуш после ревью. Схема БД **не меняется**
(деплой без `prisma db push`): отчёт живёт в `DomainMetricCache` под провайдером `aiready`.

Вопрос, на который отвечает модуль: **«насколько сайт доступен и заметен для AI-движков»**.
GEO Audit и AEO Tracker показывают следствие (не цитируют); этот экран показывает причины,
которые можно проверить бесплатно и без ключей.

---

## 0. Ловушки, ради которых написан контракт

1. **Parity — это проба по User-Agent, не по IP.** Мы шлём запрос с UA бота со своего адреса.
   WAF, который проверяет IP (Cloudflare «verified bots»), может резать нашу подделку и пускать
   настоящего бота — и наоборот. Поэтому вердикт подписан «по User-Agent», а не «бот заблокирован».
2. **Разница во времени ≠ разница по аудитории.** Браузерная базовая линия снимается дважды;
   расхождение двух браузерных ответов — это `noiseFloor` страницы. Боту засчитывается только
   расхождение сверх него (тот же принцип, что в cloaking-движке, метрика — `textSimilarity`).
3. **Не смогли прочитать ≠ плохо.** Сбой сети, 5xx у Common Crawl, недоступный справочник — это
   `null`/`unknown`, часть исключается из скора. Ноль ставится только за положительное знание.
4. **«Нет в Common Crawl» — слабый сигнал.** CC — выборка веба. Отсутствие в одном месяце ничего
   не значит, поэтому присутствие весит 20 из 100 и считается по 12 месяцам.
5. **CDX API Common Crawl нестабилен (504 на живой проверке 2026-11-15).** Присутствие читается
   из статических файлов индекса на `data.commoncrawl.org` range-запросами: бинарный поиск по
   `cluster.idx` (104 МБ, качается ~60 КБ), затем 1–3 блока `cdx-NNNNN.gz` по ~250 КБ.
6. **Файл рангов — 2.2 ГБ gzip, 118 млн доменов, отсортирован по рангу, а не по домену.** Его
   нельзя читать range-запросом и нельзя раздавать каждому инстансу. Его раз в месяц собирает
   sidecar на VPS владельца проекта; инстансы спрашивают по HTTP один домен.
7. **Скор из частей несравним, если не сказать, из каких.** Скор всегда возвращается вместе с
   `coverage` (какие части вошли), UI показывает это рядом с буквой.
8. **Прошлые месяцы CC неизменны.** Результат по паре (домен, crawl) кэшируется навсегда;
   повторный запуск дочитывает только новые и неудавшиеся месяцы.

## 2. Части и API

`part`: `"access"` (T1) · `"presence"` (T2) · `"rank"` (T3). UI вызывает их по очереди; каждая
сохраняется сама, скор пересчитывается из того, что есть. `presence` ограничена бюджетом времени
(40 с) и возвращает `pending > 0`, если месяцы остались — UI повторяет вызов.

Права: `GET` — `read`, `POST` — `write` (платных вызовов нет). Цель — всегда собственный сайт
(`Site.url` по `siteId`), домен из тела запроса не принимается.

## 3. T1 — идентичности

Базовая линия: Chrome desktop ×2. Боты: `GPTBot`, `ClaudeBot`, `PerplexityBot`, `CCBot`.
Всего 6 GET главной страницы. Вердикт бота:

| Вердикт | Условие |
|---|---|
| `inconclusive` | базовая линия сама не 2xx или получила challenge |
| `error` | сетевой сбой/таймаут |
| `challenge` | `cf-mitigated: challenge` или маркеры капчи/JS-проверки в теле |
| `blocked` | не 2xx при 2xx у браузера |
| `redirected` | другой конечный хост, чем у браузера |
| `different` | расхождение текста > `noiseFloor + 0.35` или текста < 20 % от браузерного |
| `same` | всё остальное |

## 4. T2 — присутствие

Список краулов: `https://index.commoncrawl.org/collinfo.json`, берём 12 последних.
Ключ домена в SURT: `example.co.uk` → `uk,co,example`; записи домена и поддоменов лежат в
диапазоне `[surt + ")", surt + "-")`. На месяц: `present`, `captures` (до 3 блоков, иначе
`capped`). Ошибка чтения → `present: null`, месяц остаётся в очереди.

## 5. T3 — справочник рангов

Источник: `https://data.commoncrawl.org/projects/hyperlinkgraph/<release>/domain/<release>-domain-ranks.txt.gz`,
релиз — первый `id` из `https://index.commoncrawl.org/graphinfo.json`.

Sidecar: `GET /v1/rank?d=a.com,b.com` (≤ 50) →

```json
{ "release": "cc-main-2026-may-jun-jul", "total": 118000000,
  "results": [ { "query": "blog.example.com", "domain": "example.com", "found": true,
                 "hcRank": 12345, "hcVal": 1.9e7, "prRank": 23456, "prVal": 1.1e-6, "hosts": 3 } ] }
```

Поддомен ищется как есть, затем без левых меток до двух (`blog.example.com` → `example.com`).
`GET /v1/health` → `{ ok, release, total }`. Лимит: 120 запросов в минуту с адреса.

Клиент: база из `OPENGSC_CCRANK_URL` (`off` — выключить), иначе `CCRANK_DEFAULT_URL`.
`authority = round(100 × (1 − ln(hcRank) / ln(total)))`, не найден в графе → 0.

**Тир ранга** (решение 2026-11-16, «гибрид»): рядом с авторитетом карточка называет порядок
величины места — Elite ≤ 1K · Authoritative ≤ 10K · Established ≤ 100K · Strong ≤ 1M ·
Emerging ≤ 10M · Unranked. Это подпись, без буквы и вне скора: буква на карточке одна — у скора.
Веса 50/20/30 оставлены; схема ccrank (25/35/40, знаменатель по топ-10M) сознательно не взята —
у малого сайта с открытым доступом она даёт потолок ~60.

## 6. Скор

| Часть | Вес | Состав (0–100) |
|---|---|---|
| Доступ (T1) | 50 | robots: доля разрешённых AI-ботов ×45 · parity: доля ботов с `same` ×45 · llms.txt ×10; нечитаемое исключается и веса нормируются |
| Присутствие (T2) | 20 | доля месяцев с захватами ×70 + 30, если есть в самом свежем известном месяце |
| Авторитет (T3) | 30 | `authority` |

Итог — взвешенное среднее по частям, которые есть. Буква: A ≥ 85, B ≥ 70, C ≥ 55, D ≥ 40,
E ≥ 25, F ниже. `coverage` перечисляет вошедшие части.

## 7. Чего не делаем

Path-granular robots (как и в `aiCrawl`), проверку по IP/ASN ботов, историю скора во времени,
фоновый планировщик, алерты, host-level ранги (4.5 ГБ), подмену Crawlgraph (он даёт список
ссылающихся доменов, ранги — только число).

## 8. Проверка

`npm run check`; юнит-тесты на чистые половины (классификация, SURT/бинарный поиск на
фикстуре, скор, lookup справочника). Живьём: алгоритм T2 прогнан в браузере против настоящего
`cluster.idx`. Сборка справочника на 2.2 ГБ — только на VPS, отсюда не проверяется.
