# R — Ревью и сборка волны «Октябрь»

Отдельная сессия после того, как T1…T7 сдали отчёты. Работает в worktree ветки интеграции
`.worktrees/wave-t0`, из терминала Мака.

## 1. Перед слиянием каждой ветки
1. `git diff --stat feat/wave-oct...feat/wave-oct-tN` — **каждый** файл должен быть в колонке
   этой задачи в `README.md` §4. Чужой файл — сначала разобраться, почему.
2. `git log feat/wave-oct..feat/wave-oct-tN` — нет коммитов с правкой локалей, схемы,
   `notifyI18n.ts`, `package.json`.
3. Отчёт задачи: «правки в чужих файлах», «доп. ключи», «решения не по контракту».
4. Сигнатуры сверены с `CONTRACT.md` §3. После всей сборки
   `grep -rn "not implemented (T" src` → пусто.

## 2. Порядок
```bash
git merge --no-ff feat/wave-oct-t1   # мета — независимая, самая срочная
git merge --no-ff feat/wave-oct-t3   # доставка уведомлений
git merge --no-ff feat/wave-oct-t2   # аптайм (шлёт через T3)
git merge --no-ff feat/wave-oct-t4   # индексация
git merge --no-ff feat/wave-oct-t5   # аудит (зовёт маршрут T1)
git merge --no-ff feat/wave-oct-t6   # упоминания
git merge --no-ff feat/wave-oct-t7   # доля голоса + docs/VISIBILITY.md
```
После каждого: `npm run check && npx tsc -p tsconfig.json --noEmit`. Конфликтов быть не должно:
владение файлами не пересекается. Конфликт значит, что кто-то вышел за свои файлы. Не
разрешать вслепую.

## 3. Что применить руками после слияния
- Дополнительные i18n-ключи из отчётов — во все 7 локалей (en/ru из отчёта, остальные перевести).
- `{ event: "digest" }` в вызовах `notifyUser` дайджеста — список даст T3.
- Раздел «Упоминания» из отчёта T6 — в `docs/VISIBILITY.md`.
- `CHANGELOG.md` — одна секция на волну, по пункту на задачу, пользовательским языком.
- Новые MCP-инструменты — в `docs/MCP-SETUP.md`, если там есть список инструментов.

## 4. Точечные проверки, которые ревью не должно пропустить
- **T1:** в `generate.ts` после аутлайна `title_options[0]` в полосе при любом порядке от модели;
  `pick()` нигде больше не решает судьбу меты. `forced_cut` — только после двух LLM-попыток.
- **T2:** тик с отключённой сетью не открывает инцидентов (`isCheckerOffline`); в журнал
  провайдеров не пишется по строке на каждую проверку; SSRF — монитор на `http://127.0.0.1:9091`
  получает `blocked_target`.
- **T3:** webhook с 302 на `127.0.0.1` не уходит; секреты не приходят в `GET`.
- **T4:** ручная кнопка, MCP `inspect_url` и автопроверка пишут в `InspectionQuota`; день по PT.
- **T5:** пороги мета читаются из `META_LIMITS`; новые правила с `affectsScore: false` не
  меняют health score на старом аудите (сравни score одного аудита до и после).
- **T6:** первый запуск не шлёт уведомление; редиректы Google News не раскрываются в планировщике.
- **T7:** добавление конкурента не создаёт строк в журнале провайдеров; `BrandVisibility` не
  отрисовывается дважды.
