# Бэклог после волны «Октябрь»: разбор присланных идей

По каждой идее: что уже есть в OpenGSC, стоит ли делать, в каком объёме и почему не сейчас.
Приоритет — для Руслана (трансферы, массажный салон, сетка гемблинг-сайтов) и для OpenGSC
как продукта.

## Высокий приоритет — следующая волна

### B1. Отпечатки сетки: одинаковые шаблоны title и H1 на разных сайтах
**Откуда:** находка при разборе бага с мета-тегами. Идея перекликается с «sameness reviewer»
из DispatchSEO (AGPL — только идея).
**Факт:** один и тот же шаблон стоит на четырёх сайтах сразу: «… Démo Gratuite : Jouer Sans
Inscription ni Dépôt», «Stratégie … : Bankroll et Mises — Que Faut-il Faire ?». Для сетки это
заметный отпечаток: и для ручной проверки, и для алгоритмов.
**Что сделать:** отчёт по портфелю из уже сохранённых `SiteAuditPage`: title и H1, у которых
после замены названия сущности (домен или бренд сайта → `{X}`) совпадает скелет на ≥ 2 сайтах.
Плюс опция в генераторе: «запретить скелеты title, уже использованные в портфеле».
**Стоимость:** 0, только локальные данные. Объём — одна задача.

### B2. Бэклинки: disavow, токсичность, приоритет восстановления
**Есть:** Backlinks v2 (новые и потерянные, алерты `lost_link`, `backlink_loss`, `favorite_link`),
токсичность в модуле дропов (`drops_toxicity`), Link Monitor конкурентов, Outreach.
**Нет:** генератора disavow-файла, токсичности для своего профиля, сортировки потерь по ценности.
**Что сделать:** (1) переиспользовать эвристику токсичности дропов на `SiteBacklink`: анкоры
казино и фармы на нетематических донорах, всплески доменов с одной подсети, DR 0 с тысячами
ссылок; (2) disavow-генератор — выбранные домены → `domain:x.com` с комментариями-причинами,
скачивание `.txt`; (3) приоритет восстановления потерь = DR × dofollow × трафик донора ×
«ссылка вела на страницу с кликами».
**Не делать:** «314 curated prospects» — для гемблинга такой каталог бесполезен, а для других
ниш устаревает за год.

### B3. Local SEO v1 (massagethess.gr, трансферы)
**Есть:** ничего, кроме `aeoCity` в AEO.
**Что сделать, в порядке ценности:**
1. **Локальные позиции по городу** — `TrackedKeyword.device` уже зарезервирован; добавить
   `location` (город или координаты → `uule`). У A-Parser `SE::Google` есть опция `location`,
   у DataForSEO — `location_code`. Показывать позицию в органике и отдельно — в **local pack**
   (3-pack).
2. **NAP-проверка** — название, адрес и телефон со всех страниц своего сайта плюс список URL
   каталогов (вводит пользователь): найти расхождения в написании.
3. **Шаблоны LocalBusiness-схемы** (`TaxiService`, `DaySpa`/`HealthAndBeautyBusiness`,
   `Restaurant`…) с проверкой по аудиту.
**Позже:** Google Business Profile API (посты, фото, отзывы). Доступ к API Google выдаёт
по заявке, и одобрение может занять недели. Подать заявку стоит заранее, если это нужно.
Агрегатор отзывов Yelp, TripAdvisor и Trustpilot — у них закрытые или платные API, в Греции
пользы мало.

## Средний приоритет

### B4. Trend radar (растущие запросы)
**Идеи:** TrendWatch (платный Trends MCP API, 100 запросов в месяц бесплатно), trend radar из
DispatchSEO.
**Что сделать по-нашему, бесплатно:** (1) растущие запросы из своего GSC — показы за 7 дней
против 28, новые запросы с нуля; (2) подсказки Google через A-Parser
`SE::Google::Suggest` по сид-словам ниши (для гемблинга — названия новых слотов и провайдеров).
Вывод — блок в `/demand` и строка в дайджесте. Google Trends без официального API ненадёжен —
не использовать.

### B5. Плагиат в `/seo-tools`
**Есть:** `analyze_text` (уникальность против выдачи, выдуманные числа, структура).
**Что сделать:** проверку по вебу — выборка из 8–10 «редких» предложений текста → точный
поиск в кавычках через A-Parser → доля совпадений и найденные URL. Бесплатно, но только
когда у A-Parser стабильно работают Google-прокси (сейчас капчи, см. SERP Monitor). Платная
альтернатива (Copyleaks, Originality) — отдельный провайдер с ценой до запуска.

### B6. Проверка индексации через `site:` для сайтов без GSC
Для дропов, чужих сайтов и доменов, которых нет в Search Console. Тоже через A-Parser, тоже
после стабилизации прокси. Дополняет T4, а не заменяет его.

### B7. Видимость: тональность и AI Overviews
- Тональность упоминаний в ответах ИИ — один дешёвый LLM-вызов на ответ, только по кнопке и с
  ценой до запуска.
- AI Overviews как шестой «движок» — из снимков SERP Monitor (A-Parser отдаёт `ai_answer`),
  без новых запросов.

## Низкий приоритет (продукт для агентств, не для Руслана)

### B8. Отчёты для клиентов
Есть share view (read-only ссылка). Можно добавить white-label PDF (логотип, цвет, футер),
ежемесячную рассылку отчёта через каналы T3, «что сделано за месяц» из Content Ops и Outreach.

### B9. Виджет аудита, лиды, коммерческое предложение
Есть публичный Site Health Check (`PRODUCT-ROADMAP.md` §9). Виджет — это iframe на него плюс
форма e-mail и входящие лиды с найденными проблемами. Генератор КП из аудита — позже. Прогнозы
трафика в КП не делать никогда: краулинг их не обосновывает (правильная мысль автора
All-In-One).

### B10. PWA
Манифест и установка на телефон стоят недорого. Push-уведомления дублируют Telegram. Делать,
когда дойдут руки до мобильной вёрстки целиком.

### B11. Браузерное расширение
«Отправить в OpenGSC» с любой страницы. MCP уже покрывает бо́льшую часть сценариев. Отложено.

### B12. Hreflang-менеджер
Валидатор делает T5. Генератор разметки для мультиязычных сайтов — когда появится запрос.

## Не делать

- **SEO-OPTIMIZER** (`sarvdnya4979`): в репозитории нет кода, только README и `.exe` в zip —
  типичная схема распространения вредоносных программ. Не скачивать и не запускать.
- **beyondseo** — почти целиком пересекается с GEO-аудитом. Его принцип «неизвестное не
  становится оценкой» у нас уже действует.
- **google-index-checker** как код — нечего брать: тот же API уже подключён, автоматизацию
  делает T4.
- **elmo** как код — вся ценность повторена в T7 на наших данных.
