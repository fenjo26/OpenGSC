# T1 — Подгонка мета-тегов (title / description)

**Ветка:** `feat/wave-oct-t1` от `feat/wave-oct`, worktree `.worktrees/wave-t1`.
**Владение:** см. `README.md` §4, строка T1. `judge.ts` и `mechanics.ts` **не трогаешь**.

## Проблема (с доказательствами)

Руслан сгенерировал аутлайны в `/seo-tools/outline`, по ним — тексты в `/seo-tools/text`,
собрал сайты и запустил аудит. Аудит помечает сайты красным: title длиннее 65 символов,
description длиннее 165 или короче 150. Выгрузка аудитов прода за 10 дней — 40 страниц, например:

| Страница | Длина | Title |
|---|---|---|
| golden-crown-extreme-booster.fr/strategie/ | 80 | Stratégie Golden Crown Extreme Booster : Bankroll et Mises — Que Faut-il Faire ? |
| golden-crown-extreme-booster.fr/demo/ | 76 | Golden Crown Extreme Booster Démo Gratuite : Jouer Sans Inscription ni Dépôt |
| triple-beasts-of-fortune.fr/en/demo/ | 72 | Triple Beasts of Fortune Free Demo: Play Without Registration or Deposit |
| helios-triple-sun.fr/ | 69 | Helios Triple Sun Slot : Avis Pragmatic Play 2026, RTP 96,46 % & Démo |

Description — до 181 символа (`/strategie/`) и от 128 (`/bonus/`).

Бренд к title не приклеивается: это сырые значения генератора. Картина одинаковая: длинное
название слота (18–28 символов) плюс шаблонный хвост («Démo Gratuite : Jouer Sans Inscription
ni Dépôt»). Во французском типографика `␣:␣` добавляет ещё по символу.

## Первопричина — в коде, а не в модели

1. **Длина задаётся только текстом промпта** — `prompts.ts` строки 224, 407, 733. Код её нигде
   не проверяет: ни после аутлайна, ни после текста, ни после rewrite. LLM не считает символы
   надёжно — это свойство токенизации, а не плохой промпт. Ещё одна строка в промпте не поможет.
2. **`pick()` берёт первый непустой вариант**, а не тот, что влезает (`prompts.ts:727`,
   `generate.ts:1623`, `outlineFormat.ts:69`). Из трёх `title_options` в норму часто попадает
   второй или третий, но выбирается первый.
3. **Шаблон текста разрешает модели переписать мету** («Если значение пустое — допиши…»), и
   в блоке `Title:` может оказаться уже не тот вариант, что был в аутлайне.
4. **Границы живут в двух местах**: промпт — 50–60 и «~150–155», аудит (`rules.ts`) — 50–65 и
   150–165. Цель «~150–155» почти упирается в нижнюю границу аудита: 148 — уже красный.
5. **Судья не поможет и не должен**: он работает без контекста и не видит лимиты. Учить его
   считать символы — тот же тупик, что в п. 1. Проверка должна быть детерминированной.

## Что сделать

### 1. `src/lib/seo/metaFit.ts` — чистая логика + один вызов LLM

Границы — **только** из `metaLimits.ts` (`META_LIMITS.*.targetMin/targetMax`). Длина —
`metaLength()` (code points, иначе греческий и кириллица посчитаются неверно).

**`fitMetaLocal(field, value, options, keyword, brand?)`** — без сети:
1. Нормализация каждого кандидата: trim, схлопнуть пробелы, снять markdown (`**`, `` ` ``),
   внешние кавычки, декодировать HTML-сущности (`decodeHtmlEntities` из `outlineFormat.ts`).
2. Кандидаты = `[value, ...options]` без дублей. Если `value` в полосе → `kept`.
3. Иначе первый из `options` в полосе, **где главный ключ стоит как можно раньше**
   (сравнение без регистра и диакритики) → `picked`.
4. Иначе детерминированная обрезка слишком длинного: по очереди отрезать **последний**
   сегмент по разделителям ` | `, ` — `, ` – `, ` - `, ` : `, `: `, `, `, ` & `, затем
   скобочную группу `(…)`. Останавливаться, как только длина в полосе. Нельзя: убрать
   главный ключ, оставить висящий разделитель или предлог в конце (список коротких служебных
   слов для en/fr/es/de/it/ru/el/pt — в модуле). Бренд (`brand`), если он есть, отрезается
   первым → `trimmed`.
5. Иначе `unfixable` с исходным значением: дальше решает `fitMeta`.

Для description обрезка режет по предложениям с конца, потом по `, ` и ` — `. Результат
заканчивается точкой, `!` или `?`.

**`fitMeta(item, llm)`**:
1. `fitMetaLocal` для каждого присутствующего поля.
2. Если поле не в полосе и `llm.allow` — **один** repair-вызов на оба поля сразу
   (`fetchLLM` из `@/lib/llm`, тот же провайдер/модель, что и у генерации). Промпт на русском,
   как соседние: дать исходное значение с его **точной длиной**, полосу, язык, главный ключ,
   попросить **5 вариантов** в JSON `{ "title": [..5], "description": [..5] }`. Правила:
   ключ в начале title; смысл и язык не менять; не выдумывать цифры, которых нет в исходнике.
   Варианты проверяются **кодом**; берётся первый в полосе → `llm`.
3. Ни один не подошёл → второй вызов, где в промпте перечислены длины неудачных вариантов
   («ваши варианты: 67, 71, 64 — все длиннее 60»). Максимум 2 вызова на элемент.
4. Всё ещё мимо → `forced_cut`: срез ≤ `targetMax` по границе слова с правилами из п. 4. Для
   слишком короткого — `unfixable`, значение не трогать: дописывать «воду» кодом нельзя.
5. `llmCalls` в ответе — реальное число вызовов.

**`readMetaBlock` / `writeMetaBlock`** — работа с блоком
```` ```\nTitle: …\nMeta Description: …\nURL Slug: …\n``` ```` в начале статьи (формат —
`ensureMetaBlock` в `generate.ts`). Регистронезависимо, с блоком и без обрамляющих ```` ``` ````.

### 2. Встроить в генерацию

- **Аутлайн** (`generate.ts`, `genOutline` — там, где уже вызывается `fixYear` на
  `title_options` около строки 767, и после `localizeOutlineHeadings`, строка ~369): прогнать
  все `title_options` и `description_options` через `metaLength` и **переупорядочить**, чтобы
  варианты в полосе стояли первыми. Тогда `pick()` и `outlineFormat.ts` автоматически берут
  подходящий, и чужие файлы менять не нужно. Если в полосе нет ни одного варианта, вызвать
  `fitMeta` с `allow: true` (генерация и так платная, провайдер известен) и поставить
  результат первым.
- **Текст** (`genText`, сразу после `ensureMetaBlock`, строка ~1484): `readMetaBlock` →
  `fitMeta` (кандидаты = значение из блока + варианты аутлайна) → `writeMetaBlock`.
- **Rewrite** (`rewrite.ts`, `rewriteBatch.ts`): тот же шаг там, где собирается итоговый
  текст с метой (промпт `prompts.ts:407` возвращает `title_options`/`description_options` —
  их прогоняй так же, как в аутлайне).
- **Промпты** (`prompts.ts`): в трёх местах заменить числа на значения из `META_LIMITS`
  (интерполяция) и убрать «Если значение пустое — допиши подходящее по правилам» для Title и
  Description: пустое значение теперь заполняет код. Описание в промпте — «150–160», а не
  «~150–155». Отдельно попросить модель **не менять** Title и Description из блока.
- **Диагностика**: результат `MetaFitResult[]` клади в `meta.diagnostics.metaFit` результата
  задачи — туда же, куда уже кладутся `mechanics` и `judgeConcerns` (смотри, как `importJob`
  поднимает их в историю; если поле теряется при импорте, допиши его рядом). `forced_cut` и
  `unfixable` дополнительно попадают в `needsAttention` / concerns — это не блокер, работа
  не выбрасывается (так же, как у судьи).

### 3. API и UI

- `POST /api/seo/meta-fit` — по контракту §4. Без `allowLlm` работает `fitMetaLocal` и
  бесплатен (`act`). С `allowLlm` нужно право `spend`, ключи провайдера берутся так же, как
  их берёт генерация на сервере (посмотри, откуда их берёт `genText`). С `historyIds` читает
  `SeoHistory` (`data` — строка статьи), применяет `writeMetaBlock` и сохраняет. Лимит — 50
  элементов за запрос.
- `SeoTextDetail.tsx`: над статьёй плашка «Мета-теги»: `Title 57/60 ✓` /
  `Title 72/60 — слишком длинный`, то же для description. Метод (`metaFitMethod_*`) — во
  всплывающей подсказке. Если что-то вне полосы — две кнопки: `metaFitRunFree`, а при неудаче
  `metaFitRunLlm` с `confirm()`-текстом `metaFitConfirm` (n = число вызовов, максимум 2).
- MCP `fit_meta` (`toolsMeta.ts`): `items[]`, `allow_llm`, `confirm`. Без `confirm: true` при
  `allow_llm` — ошибка с объяснением, как у остальных платных инструментов.

### 4. Уже собранные сайты

Руслану нужно исправить мету на уже опубликованных страницах. Путь такой: T5 добавляет в
аудите кнопку `metaFitSuggest` у проблем с title и description, которая вызывает твой

принимал `items` без `historyIds` и возвращал результат, ничего не сохраняя.

## Тесты — `src/lib/seo/metaFit.test.ts`

Сохрани две проверки T0 (инварианты `META_LIMITS`, `metaLength` на греческом). Дальше —
только `fitMetaLocal`, `readMetaBlock`, `writeMetaBlock`; сеть не нужна.

- «Stratégie Golden Crown Extreme Booster : Bankroll et Mises — Que Faut-il Faire ?» (80) →
  `trimmed`, «Stratégie Golden Crown Extreme Booster : Bankroll et Mises» (58).
- «Golden Crown Extreme Booster Démo Gratuite : Jouer Sans Inscription ni Dépôt» (76) →
  отрезание хвоста даёт 42, это ниже полосы → **`unfixable`** локально, значение не тронуто.
  Этот тест важнее предыдущего: обрезка не должна возвращать результат вне полосы. Такие
  случаи решает LLM-шаг.
- «Helios Triple Sun Slot : Avis Pragmatic Play 2026, RTP 96,46 % & Démo» (69) → после
  отрезания ` & Démo` получается 62, после `, RTP 96,46 %` — 49. Оба вне полосы → `unfixable`.
- Первый вариант 70, второй 55 → `picked`, выбран второй.
- Title, который нельзя обрезать без потери ключа, → `unfixable` (а не обрезка ключа).
- Description 181 → обрезано по предложению, заканчивается точкой, в полосе.
- Description 128 → `unfixable` (без LLM коротышку не удлиняем).
- Обрезка не оставляет в конце ` :`, ` —`, ` &`, ` de`, ` à`, ` и`, ` для`.
- `readMetaBlock` / `writeMetaBlock`: блок в ```` ``` ```` и без них; текст без блока не
  меняется; повторная запись идемпотентна.
- Кириллица и греческий: длина считается по code points, обрезка не рвёт слово.
