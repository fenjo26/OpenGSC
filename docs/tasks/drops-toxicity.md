# T-TOX — стадия «токсичность» в конвейере /drops

Ядро написано и протестировано (`src/lib/drops/toxicity/`, 24 теста, `npx tsx --test` зелёные).
Задача — подключить его: стадия, хранение, UI, MCP. Логику классификатора не переписывать.

## Куда встаёт

Конвейер становится шестишаговым:

```
импорт → [скан имён] → DNS-префильтр → реестр → свободные → [токсичность] → покупка
```

- **Скан имён** — бесплатный и мгновенный, прямо на импорте: `scanDomainName()` без единого запроса. На списке из 4864 доменов помечает 8. Это не отсев, а метка «посмотреть первым».
- **Токсичность** — после реестра, а не до. К этому моменту список короткий: проверять вебархивом 5 тысяч строк, из которых 90% заняты, бессмысленно.

## Что делает эта задача

### 1. Сборщик — `src/lib/drops/toxicity/collect.ts` (новый)

```ts
export async function collectEvidence(
  domain: string,
  opts: { snapshots?: number; fetch: SafeFetch },
): Promise<DomainEvidence>;
```

Последовательность на домен: `buildCdxUrl(domain, { last: 3 })` → `parseCdxJson` → `usableRows` → для каждой строки `rawSnapshotUrl(ts, original)` → `extractTitle` + `extractTextSample` + `extractMetaRefresh`.

- Первый снимок тянем `Range: bytes=0-16383` — титул лежит в начале; при 200 вместо 206 просто обрезаем по `maxBytes`.
- Суффикс `id_` обязателен: без него парсится разметка архива, а не сайта.
- 4 запроса на домен (CDX + 3 снимка). **Гнать через существующий пул `DropProxy`**, добавив `web.archive.org` как отдельную зону с собственным `minIntervalMs`: archive.org лимитирует по IP, и без пула тысяча доменов растянется на часы. 429 и 503 — бэкофф 6/12/24 ч, как в реестровой стадии, и это не «занят», а «переспросить».
- Стадия батчевая, с клиентским циклом и стоп-флагом через `useRef` — копия того, что уже сделано для DNS и реестра.

### 2. Хранение

На `DropCandidate` четыре поля: `toxVerdict` (`clean|empty|suspicious|toxic`), `toxScore` (Int), `toxCheckedAt` (DateTime), `toxSignals` (Json). Снимки с титулами — в `DropEvent`, чтобы карточка показывала то же, что видел классификатор, и вердикт можно было перепроверить без повторного обхода.

Правила репозитория: `schema.prisma` и `schema.mysql.prisma` правятся вместе, `@db.VarChar(500)` на строковые поля в индексах, миграция пишется руками, `prisma db push` перед стартом.

### 3. Связь с платным AI-проходом

`drops_history_ai` перестаёт быть первой линией. Кнопка запускает его **только на `needsDeepCheck(report)`** — то есть на `suspicious` и на «снимков нет». `toxic` и `clean` вынесены бесплатно и в модель не едут. Это основная экономия задачи.

### 4. UI

- Колонка/чип «Токсичность» с четырьмя состояниями и фильтром по ним, рядом с существующими чипами воронки.
- Раскрывающаяся карточка домена: три снимка с датами и титулами (как на референсном скриншоте), но **с причинами**: под каждым титулом — сработавшие сигналы (`gambling_zh: 利来, 九游`, `alien_script: cjk в зоне .com`). Вердикт без причины бесполезен, потому что именно там прячется ошибка калибровки.
- Счёт показывать числом рядом с вердиктом.
- Бейдж скана имён на строке импорта.

### 5. MCP и экспорт

`drops_list` отдаёт `toxVerdict`/`toxScore` в строке; в фильтры добавить `tox`. В `GET /api/drops/export` — две колонки.

### 6. i18n

~18 ключей `dropsTox*` во все 7 локалей одной задачей. Коды сигналов — ключами `dropsToxSignal_<code>`, список кодов экспортировать массивом и проверять тестом на совпадение с ключами (как `serpmonProblem_*`).

### 7. Регистрация тестов

В `package.json` дописать в конец `test:unit` глоб `src/lib/drops/toxicity/*.test.ts`. Порядок существующих записей не менять.

## Калибровка — что важно не сломать

1. **Абсолютный порог, а не доля.** Два иероглифа в титуле — факт, сколько бы рядом ни было латиницы. Порог по доле пропускает `mile米乐·m6(中国区)官方网站` — ровно то, на чём ошибается референсный чекер.
2. **Письменность и тематика — разные сигналы.** Китайский титул в `.cn` не значит ничего. Он же в `.de` — значит.
3. **Свежесть.** Флип 2015 года весит 0.35, прошлогодний — 1. Домен, переживший гембл десять лет назад, и домен, слитый в прошлом месяце, — разные покупки.
4. **Общие слова не выносят вердикт в одиночку.** `casino`, `slot`, `betting` весят 25 и дают `suspicious`, а не `toxic`: `casinoonwheels.de` — прокат оборудования для корпоративов, и он в списке есть.
5. **Имена не матчатся подстрокой без разбора.** `judi` внутри `judith-meyer-design.de`, `depo` внутри `reliabledeposits.org`, `pharmacy` в настоящей аптеке. Поэтому `NAME_TOKENS` — отдельный короткий список, а не все словари.

- `check:i18n` — 7 локалей идентичны; `eslint` — 0 новых ошибок; узкий `tsc` чист.
- Ручной прогон на 20 доменах из свежего рана: вердикты сверить глазами по карточкам, посчитать ложные срабатывания. Если `suspicious` больше трети — поднимать пороги, а не расширять словари.
- Проверить, что 429 от archive.org не записывается как `clean`: отказ — не вердикт, строка остаётся непроверенной и возвращается по бэкоффу.
