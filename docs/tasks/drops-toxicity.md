# T-TOX — токсичность дропа (редакция 2, по живой схеме)

Ядро в репозитории: `src/lib/drops/toxicity/`, 28 тестов, зелёные.
Эта редакция **заменяет первую целиком**. Первая писалась вслепую и предлагала
отдельные колонки `toxVerdict`/`toxScore` — это было неверно.

## Что выяснилось по живой базе

`DropCandidate` уже содержит всё нужное:

```
historyVerdict TEXT    historyNote TEXT    historyAt DATETIME
veto TEXT              score REAL          topAnchors TEXT
waybackSnapshots INT   waybackFirstAt      waybackLastAt    waybackGapDays
```

Отсюда два следствия, на которых построена эта редакция:

1. **Фаза 1 не меняет схему вообще.** `prisma db push` не нужен. Классификатор
   пишет в `historyVerdict` / `historyNote` / `historyAt` — те же поля, куда
   писал платный AI-проход. Вето `spam_history` при этом **не поднимается**.
2. **`topAnchors` уже лежит на строке.** Это бесплатный и более сильный
   источник, чем снапшоты: анкор пишет донор, а не владелец домена, подделать
   его в свою пользу нельзя. Ядро это уже умеет — `classifyAnchors()`, вес 50
   против 35 у письменности в титуле, множитель свежести к анкорам не
   применяется (это сегодняшний профиль, а не история).

## Теневой режим — первый пункт, не последний

Вето `spam_history` обнуляет скор и выкидывает строку из покупательской выборки
`noVeto`. Любое ложное срабатывание молча убирает нормальный домен из списка, и
человек об этом не узнает: строка просто не покажется.

Поэтому связка «вердикт → вето» ставится **за настройку модуля**, по умолчанию
выключенную:

- **Фаза 1 (по умолчанию).** Пишем `historyVerdict`, `historyNote` (счёт и
  сработавшие коды), `historyAt`. `veto` и `score` не трогаем. Вердикт в таблице
  видно, на выборку он не влияет.
- **Фаза 2 (после калибровки).** Флаг включается, `historyVerdict = 'toxic'`
  начинает поднимать `veto = 'spam_history'` в том же месте, где это делает
  AI-проход. Нового пути в скоринге не появляется.

Калибровка между фазами: прогнать по каталогу (сейчас 59 строк), просмотреть
два-три десятка карточек глазами, посчитать ложные. Если `suspicious` больше
трети — поднимать пороги (`toxicAt` / `suspiciousAt` — параметры
`classifyDomain`), а не расширять словари.

## Порядок источников — от бесплатного к дорогому

```
0. анкоры (topAnchors)   уже в базе, 0 запросов           classifyAnchors
1. скан имени            0 запросов                       scanDomainName
2. снапшоты вебархива    CDX + до 3 снимков на домен      collectEvidence
3. AI-проход             платный, только needsDeepCheck()
```

Шаги 0 и 1 гонять по всему каталогу сразу — они бесплатны. Шаг 2 — только после
реестровой стадии, по коротким спискам. Шаг 3 — по кнопке и только по тому, что
вернул `needsDeepCheck()`.

## 1. Сборщик — `src/lib/drops/toxicity/collect.ts` (новый)

```ts
export async function collectEvidence(
  domain: string,
  opts: { snapshots?: number; anchors?: string[]; fetch: SafeFetch },
): Promise<DomainEvidence>;
```

`buildCdxUrl(domain, { last: 3 })` → `parseCdxJson` → `usableRows` → на каждую
строку `rawSnapshotUrl(ts, original)` → `extractTitle` + `extractTextSample` +
`extractMetaRefresh`. Анкоры прокидываются из `topAnchors`, без сети.

- Первый снимок тянуть с `Range: bytes=0-16383`; при 200 вместо 206 резать по
  `maxBytes`. Титул лежит в начале, а дорвеи бывают на десятки мегабайт.
- Суффикс `id_` обязателен, иначе парсится разметка архива, а не сайта.
- Гнать через существующий пул `DropProxy`, добавив `web.archive.org` отдельной
  зоной с собственным `minIntervalMs`: archive.org лимитирует по IP.
- **429 и 503 — не вердикт.** Строка остаётся непроверенной и возвращается по
  бэкоффу 6/12/24 ч. Тот же инвариант, что в реестровой стадии.
- Стадия батчевая, клиентский цикл, стоп-флаг через `useRef` — копия DNS и реестра.

Фетчер `glue/fetchPages.ts` уже написан и умеет ручные редиректы, лимит хостов и
Range-ретрай — брать его за образец, а где сходится, переиспользовать.

## 2. Хранение

`historyVerdict` — вердикт ядра. `historyNote` — компактная строка вида
`score 95 · gambling_zh(利来,九游) · alien_script(cjk) · anchor_gambling_id(togel)`.
`historyAt` — время прогона. Снапшоты с титулами — в `DropEvent`, чтобы карточка
показывала ровно то, что видел классификатор, и вердикт можно было перепроверить
без повторного обхода.

Понадобится машинночитаемый разбор сигналов — добавлять колонку тогда. Фаза 1
обходится без миграции, и это надо проверить явно при приёмке.

## 4. MCP

Новых сущностей не заводить, расширить существующие.

**`drops_toxicity`** — новая, класс `net` (ходит в archive.org), не `paid`:

```
domains?: string[]     // до 25 за вызов
filter?: object        // фильтр в форме drops_list, альтернатива domains
```

не отработал бесплатный классификатор. Сейчас его можно позвать вслепую и сжечь
кредиты на очевидном китайце.

## Калибровка — что не сломать

1. **Абсолютный порог, а не доля.** Два иероглифа в титуле — факт. Порог по доле
   пропускает `mile米乐·m6(中国区)官方网站`, на чём и ошибается референсный чекер.
2. **Письменность и тематика — разные сигналы.** Китайский титул в `.cn` не значит
   ничего, он же в `.de` значит.
3. **Свежесть.** Флип 2015 года весит 0.35, прошлогодний — 1. К анкорам множитель
   не применяется.
4. **Общие слова не выносят вердикт в одиночку.** `casino`, `slot`, `betting`
   весят 25 и дают `suspicious`: `casinoonwheels.de` — живой прокат оборудования
   для корпоративов, и он есть в реальном списке.
5. **Имена не матчатся подстрокой без разбора.** `judi` внутри
   `judith-meyer-design.de`, `depo` внутри `reliabledeposits.org`, `pharmacy` в
   настоящей аптеке. Поэтому `NAME_TOKENS` — отдельный короткий список.
