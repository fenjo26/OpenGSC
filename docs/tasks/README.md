# Backlinks v2 — параллельная разработка

Семь задач. Все стартуют одновременно, каждая в своей ветке и своей сессии.
Разрезаны **не по этапам, а по владению файлами** — так, чтобы merge не превращался
в разбор конфликтов.

Перед началом любой задачи прочитай `CONTRACT.md`. Это единственный источник правды
по именам моделей, полей, типов и i18n-ключей. Если тебе кажется, что в контракте
ошибка — **не исправляй молча**, напиши об этом в отчёте: остальные шесть задач уже
пишут код против этих имён.

## Про локали — читай внимательно

`npm run check:i18n` требует, чтобы наборы ключей в **семи** файлах (`en, ru, uk, fr, es, de, zh`)
совпадали до последнего ключа. Если пять веток допишут свои ключи в семь файлов,
каждый merge будет конфликтом, а `check` будет падать до последнего.

Поэтому: **все ключи для всех задач создаёт T0, заранее.** Твоя задача перечисляет
нужные ей ключи в своём ТЗ (T0 их оттуда соберёт и переведёт), а ты в коде просто
пользуешься `t("bluiImport")` и т.п. — ключ уже будет.

Если тебе по ходу понадобился ключ, которого нет в твоём списке: **не добавляй его
в локали**. Допиши его в раздел «Дополнительные ключи» своего ТЗ-файла и используй
в коде — T0 или ревьюер их доберёт.

## Что нельзя

- **Не запускай `prisma migrate dev`.** Он сгенерит папку миграции с другим таймстемпом,
  и у семи веток будет семь разных миграций одного и того же. Миграцию пишет T0 руками
  (см. его ТЗ), остальные не трогают `prisma/` вообще.
- **Не переименовывай и не удаляй существующую модель `Backlink`** и не ломай
  `/api/backlinks/check-alive` и `/api/backlinks/check-xr`. Эта волна добавляет
  рядом, а не заменяет. Старые данные переносит миграция T0.
- **Не тяни поля `traffic`, `traffic_domain`, `refdomains_source`** в запросах к Ahrefs.
  Они стоят 10/10/5 юнитов против 1 и утраивают счёт пользователя. Причём поля,
  названные в `where` и `order_by`, биллятся тоже, даже если не возвращаются.

## Как проверить свою работу перед сдачей

```bash
npm run check          # i18n + release + unit-тесты; должно пройти целиком
npx tsc -p tsconfig.json --noEmit
```

Известный пре-existing баг, не твоя регрессия: `src/lib/scanner/exportMd.ts:103`, TS2352.
Полный `tsc` по всему приложению долгий — если торопишься, сделай временный узкий
`tsconfig` с `include` только на свои файлы, но перед сдачей прогони полный.

## Отчёт по задаче

В конце работы напиши в чат сессии:

1. Что сделано, файл за файлом.
2. Чего **не** сделал и почему (упёрся в чужой файл, не хватило контракта, и т.п.).
3. Правки, которые нужны в чужих файлах — списком, чтобы ревьюер применил.
4. Дополнительные i18n-ключи, если появились.
5. Что именно ты проверил и как (команда + результат).
6. Места, где ты принял решение не из контракта, — с обоснованием.

Ревью и сборка веток — на отдельной сессии, после того как задачи закроются.
