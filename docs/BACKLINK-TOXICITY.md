# Бэклинки: токсичность, disavow, восстановление

Модуль отвечает на три вопроса о **своём** ссылочном профиле (Backlinks v2, `SiteBacklink`),
которые раньше не задавались вовсе: какие доноры для этого сайта токсичны, что нести в
Google Disavow, и какую потерянную ссылку возвращать первой.

**Стоимость: бесплатно.** Классификация — локальная математика по уже выгруженным строкам.
Глубокая проверка — HTTP-запросы к донорам с вашего сервера (сеть, но не деньги). Платных
API модуль не вызывает вообще.

## Главная ловушка — своя ниша

Классификатор дропов (`src/lib/drops/toxicity`) считает казино, ставки и адалт токсичными —
для дропа это верно. Для **живого сайта** казино-анкор с казино-донора — нормальная
тематическая ссылка: сайт сам может быть казино. Поэтому у сайта есть
`Site.backlinkNiche = { ownNiche: ["gambling", …] }` — коды групп маркеров, которые для него
**не** токсичны:

- элемент ниши совпадает с кодом группы целиком (`"gambling_zh"`) или как префикс до `_`
  (`"gambling"` покрывает `gambling_zh`, `gambling_id`, `gambling_generic`);
- сигналы этих групп подавляются и в титулaх/сниппетах, и в анкорах (`anchor_`-двойники);
- всё остальное (фарма, адалт, реплики, чужая письменность, взлом) токсично как обычно.

Если ниша не задана, UI предлагает её по сайту: группы маркеров из title и description
главной страницы последнего завершённого аудита. **Предложение, а не автоприменение** —
оператор видит чипы и сохраняет сам (`PUT /api/backlinks/toxicity/niche`).

Группы маркеров: `gambling_zh` (китайский гембл), `gambling_id` (индонезийский),
`gambling_generic` (casino/slot/jackpot — слова, встречающиеся и у легального бизнеса),
`adult`, `pharma`, `replica`, `essay_mill`.

## Сигналы и оценка донора

Вердикт пишется **всем строкам одного донора** (DR, контентность и анкоры — свойства донора,
посрочный пересчёт усреднил бы sitewide-помойку до «чисто»). Сигналы:

| сигнал | код | вес |
|---|---|---|
| маркеры в титулe донора / сниппете / глубокой проверке | `<группа>` | вес группы (25–60) |
| маркеры в анкорах | `anchor_<группа>` | вес группы +15, 20..60 |
| чужая письменность в титулe | `alien_script` | 25 (CJK — 35) |
| чужая письменность в анкорах | `anchor_alien_script` | 30 |
| sitewide-помойка: DR < 5 и ≥ 20 ссылок | `sitewide_low_dr` | 40 |
| все ссылки вне контента (≥ 10) | `out_of_content` | 25 |
| домен-парковка по титулу | `donor_parked` | 45 |

Оценка 0…100 — сумма весов: **≥ 60 → toxic, ≥ 25 → suspicious, иначе clean**. Нет ни анкора,
ни титула, ни структурного сигнала → **unknown** — «не проверяли», а не «чисто» (`null ≠ 0`).

«Чужая письменность» считается относительно **зоны самого сайта** (`isNativeScriptForZone`):
китайские анкоры на греческом гемблинг-сайте — сигнал; на сайте в зоне `.cn` — родные. Латиница
не сигнал нигде.

### Переоптимизация — сигнал профиля, не донора

Доля точных коммерческих анкоров (деньговые слова: buy/price/заказать/…, не URL и не бренд
сайта) выше 30 % при ≥ 10 анкорах — баннер в UI. На уровень доноров не влияет: «у вас слишком
много точных вхождений» и «этот донор спам» — разные диагноза.

### Глубокая проверка

По кнопке и только для `suspicious`-доноров: `safeFetch` главной страницы донора (до 50 доменов
за раз, через тот же `fetchDonorPage`, что проверка плейсментов), title + фрагмент текста — те
же маркеры. Сеть, но не деньги.

## Прогон и алерт

- `POST /api/backlinks/toxicity/run { siteId, limit? }` — пересчитать сайт (`limit` = сколько
  suspicious-доноров глубоко проверить, 0..50). Ручной прогон алерты не шлёт.
- Планировщик (`src/lib/backlinks/scheduler.ts`) тикает раз в час: сайт пересчитывается, если
  есть строки с `toxCheckedAt = null` (включая CSV-импорт) или старше последней завершённой
  синхронизации `SiteBacklinkSync` — то есть «пришли новые доноры».
- После пересчёта: появились доноры, ставшие `toxic` (не были toxic в прошлом прогоне) —
  **одно** уведомление `toxicNewTitle/toxicNewMsg` (≤ 10 доменов), событие `alert`, дедуп через
  `AlertEvent` (`type: "toxic_new"`, `dedupeKey: toxic:<siteId>:<UTC-день>`).
- Первый прогон по сайту молчит — иначе весь исторический профиль придёт одним сообщением.

## Disavow

`disavow` **никогда не ставится автоматически** — только явный PATCH оператора
(`/api/backlinks/disavow`, выбор: `ids[]` строк, `domains[]` доноров или «все toxic»).
Дополнение к контракту: `domains[]` и `allToxic` — расширение формы `{ ids[], disavow, note? }`
для массовых действий UI (перегонять сотни id через браузер незачем), семантика та же.

`GET /api/backlinks/disavow?siteId=&mode=domain|urls` → `text/plain; charset=utf-8`,
`Content-Disposition: attachment; filename="disavow-<host>-<date>.txt"`:

```
# OpenGSC disavow file for example.com — generated 2026-11-02
# Upload: https://search.google.com/search-console/disavow-links
# toxic · pharma, anchor_adult · 14 links
domain:spam-donor.xyz
```

- уровень `domain:` — по умолчанию, но только для доноров, у которых отмечены **все** ссылки
  профиля; частично отмеченные разворачиваются в отдельные URL;
- `mode=urls` — отдельные URL везде (переключатель в UI);
- комментарий-причина — из `disavowNote` оператора или из кодов сигналов;
- пустая выборка → только заголовок (это валидный файл, очищающий прежний disavow).

В UI обязательное предупреждение: Google рекомендует disavow только при ручных санкциях или
явно купленных/спамных ссылках; ошибочный disavow отключает хорошие ссылки. Share-вид (гостю
по токену) вкладку Disavow не показывает вовсе — это решение оператора, а не материал отчёта.

## Приоритет восстановления

Потерянная строка: `apiLost`, или `checkStatus = "missing"`, или `checkTargetOk = false`,
или донорское событие `rel_downgraded` (переход dofollow → nofollow/sponsored — именно
**событие**: каждая nofollow-ссылка когда-либо купленная не должна заливать таблицу).

Оценка = `DR-вес (apiDr/100, минимум 0,05) × (dofollow ? 1 : 0,3) × (apiContent ? 1 : 0,5)
× (1 + log10(1 + клики urlTo за 28 дней)) × свежесть (≤30д — 1, ≤90д — 0,6, дальше — 0,3,
неизвестно — 0,6) × (favorite ? 1,5 : 1)`.

Тип действия: `page_alive_link_removed` (страница жива, ссылки нет — писать вебмастеру) ·
`page_dead` (404/мёртв — просить восстановить или редирект) · `nofollowed` · `retargeted`
(ведёт не на ту страницу) · `unknown` (Ahrefs говорит «потеряна», нашей проверки не было —
сначала проверить). Кнопка «В Outreach» создаёт проспект через тот же серверный сервис, что
MCP `save_outreach_prospect` (`POST /api/outreach`).

## Маршруты и права

| маршрут | право |
|---|---|
| `GET /api/backlinks/toxicity?siteId=` | read (+ share-токен, только чтение) |
| `POST /api/backlinks/toxicity/run` | act (сеть при глубокой проверке, бесплатно) |
| `PUT /api/backlinks/toxicity/niche` | act |
| `GET /api/backlinks/disavow?siteId=&mode=` | read, только владелец |
| `PATCH /api/backlinks/disavow` | act |
| `GET /api/backlinks/recovery?siteId=` | read (+ share-токен) |

MCP: `get_backlink_toxicity` (local), `get_disavow_file` (local, текст файла). Инструмента
«пометить disavow» нет намеренно.

## Код

- `src/lib/backlinks/toxicity.ts` — чистая классификация (ниша, маркеры, письменность,
  структура, переоптимизация); тесты `toxicity.test.ts`;
- `src/lib/backlinks/disavow.ts` — чистый сборщик файла; тесты `disavow.test.ts`;
- `src/lib/backlinks/recovery.ts` — чистая оценка потерь и типы действий; тесты
  `recovery.test.ts`;
- `src/lib/backlinks/store.ts` — прогон, ниша (+ предложение из аудита), файл, таблица
  восстановления, алерт `toxic_new`;
- `src/lib/backlinks/scheduler.ts` — часовой тик;
- UI: вкладки внутри `BacklinkProfile.tsx` — компоненты `src/components/backlinks/`.

Таблицы без миграции не роняют маршруты: ответ `{ notMigrated: true }` с подсказкой
`npx prisma db push`.
