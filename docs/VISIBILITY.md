# Видимость (вкладка сайта)

Вкладка **«Видимость»** (бывшая «AI Visibility»; ключ `aeo` в URL остался для совместимости
deep-link'ов) собирает на одном экране всё, что отвечает на вопрос «насколько заметен мой бренд
там, где люди теперь спрашивают»: в ответах ИИ-движков, в новостях, в Википедии и в том, что
LLM вообще читают. Ключ вкладки — `?tab=aeo`, подвкладка — `?tab=aeo&vis=<key>`.

Подвкладки четыре:

| Подвкладка | `vis=` | Что это |
|---|---|---|
| **Ответы ИИ** | `ai` | AEO-трекер: живые проверки. Ваши вопросы задаются ChatGPT, Perplexity, Claude, Grok и Gemini с настоящим веб-поиском, по вашим ключам; шестой движок — Google AI Overviews по этому же вопросу. У каждого упоминания — тональность. Каждый ответ сохраняется целиком — текст, цитаты, позиция вашего домена среди них |
| **Доля голоса** | `sov` | Агрегаты по уже сохранённым ответам: доля голоса против конкурентов, доля цитирований, разбивка по движкам, недельная динамика, рейтинг цитируемых доменов, распределение тональности «вы и конкуренты» |
| **Упоминания** | `mentions` | Упоминания бренда в Google News и Википедии/Wikidata, раз в день, по бесплатным открытым источникам |
| **LLM Mentions** | `llm` | Индекс DataForSEO: что LLM отвечают по вашим запросам вообще, включая вопросы, которые вы не отслеживаете |

В read-only share-виде остаются только аналитические подвкладки — те, что не тратят денег и не
имеют кнопок действий.

## Ответы ИИ

Ядро — таблица «вопрос × движок», где для каждой пары видно: процитирован / упомянут / нет.
Строка разворачивается в полное доказательство: текст ответа, все процитированные домены (ваш
выделен), ваша позиция среди них, какая модель отвечала и был ли живой поиск. «Не процитирован»
без поиска — не то же утверждение, что «не процитирован» после поиска, и трекер их не смешивает.

- **Движки:** ChatGPT (Responses API + `web_search`), Perplexity (sonar, поиск встроен),
  Claude (Messages API + серверный `web_search`), Grok (Live Search), Gemini
  (`generateContent` + инструмент `google_search` с grounding), **AI Overviews** (N7).
- **AI Overviews (N7).** Модель ничего не спрашивается — вопрос прогоняется через обычную
  выдачу Google, и из неё берётся блок AI Overview. Поставщик выдачи — DataForSEO
  (SERP Advanced, ключ тот же, что у SERP-инструментов) или, если ключа нет, ваш A-Parser
  (`SE::Google`, поля `ai_answer`/`ai_type`); DataForSEO приоритетнее. Источники обзора
  становятся цитатами; у A-Parser ссылок в ответе нет — вердикт по тексту. Нет ни ключа
  DataForSEO, ни подключения A-Parser → движок показан прочерком с подсказкой, что нужно.
- **Статус `no_overview`.** Google может отдать выдачу без AI Overview по конкретному вопросу.
  Это не «не процитирован» — у движка просто не было возможности процитировать кого-либо, —
  поэтому такой ответ имеет собственный статус и **не входит в знаменатель долей** на
  «Доле голоса»: пара (вопрос, AI Overviews) покидает окно, а не тянет за собой старый ответ.
- **Ключи:** ChatGPT/Claude/Gemini переиспользуют ключи AI-провайдеров из
  Settings → API keys (`aiKey_openai` / `aiKey_anthropic` / `aiKey_gemini`), Perplexity и
  xAI — отдельные ключи в Settings → SEO Tools. Ключ Gemini — тот же, что у провайдера
  «Google Gemini» в SEO Tools; отдельной настройки не нужно. AI Overviews настраек не имеет:
  он берёт ключ DataForSEO или подключение A-Parser, уже настроенные для SERP-инструментов.
- **Стоимость:** каждая проверка — платный вызов на вашем ключе (у Gemini grounding платен
  сверх бесплатного лимита Google; AI Overviews — запрос DataForSEO по тарифу SERP Advanced,
  либо трафик вашего A-Parser). Поэтому автопроверка выключена по умолчанию, а ручная
  «Проверить всё» спрашивает подтверждение. Модель для Gemini — текущая Flash из общей таблицы
  моделей приложения (константа `AEO_GEMINI_MODEL` в `src/lib/seo/aeo.ts`).
- **Цитаты Gemini:** grounding возвращает ссылки-редиректы `vertexaisearch.cloud.google.com`.
  Домен источника берётся из заголовка цитаты, если он похож на хост; иначе поле остаётся
  пустым. Редиректы сознательно не раскрываются — это был бы ещё один сетевой запрос на каждую
  цитату каждого ответа.
- **Идеи вопросов** (`aiSuggestTitle`): запросы из Search Console за 28 дней, по форме
  похожие на вопрос (how/what/best/как/что/лучший/πώς/τι… либо содержат «?»), минус уже
  отслеживаемые. Чтение локальное — бесплатно. Добавление идеи идёт тем же путём, что и ручной
  ввод; платить за проверку — отдельное решение.

## Тональность ответов (N7)

Трекер знал, **упомянут** ли бренд. Тональность отвечает на вопрос «**как**»: «надёжный
перевозчик» и «много жалоб на опоздания» больше не выглядят одинаково.

- **Что анализируется.** Только ответы со статусом `cited` или `mentioned` — оценивать ответ,
  в котором бренда нет, нечему. Модель видит не весь ответ, а фрагменты вокруг упоминаний
  (±2 предложения, суммарно ≤ 1500 символов) — контекста для тона достаточно, а платить за
  пересказ всего ответа не нужно.
- **Один дешёвый вызов на ответ** на провайдере/модели из настроек SEO Tools — тот же
  пер-task слот «judge», что у QA-судьи контента (самый дешёвый слот, который вы сознательно
  настроили). Выход: `{sentiment: positive|neutral|negative|mixed, score: -1..1, note}` —
  `note` до 300 символов на языке ответа. Невалидный ответ модели → поля остаются `null`
  («не оценено», не «нейтрально» и не 0).
- **Цена видна до запуска:** кнопка «Оценить тональность» сначала показывает
  «N ответов · примерно ≈N × LLM» и только после подтверждения тратит кредиты.
- **Автооценка выключена по умолчанию.** Переключатель «Оценивать новые ответы автоматически»
  в настройках AEO: когда включён, планировщик оценивает свежие ответы сразу после проверки
  (и ручная «Проверить всё» тоже). Выключен — тональность считается только кнопкой.
- **Уже оценённые ответы не переоцениваются:** поле не `null` — ответ пропускается.
- **UI:** у ответа в развёрнутой строке — бейдж тональности (иконка + подпись + score),
  заметка модели — во всплывающей подсказке. На «Доле голоса» — распределение тональности
  «вы и конкуренты»: ваша колонка считается бесплатно из уже сохранённых данных, конкурентские
  вердикты появляются после платного прогона (один вызов на ответ покрывает все бренды в нём;
  у конкурентских вердиктов нет своей колонки в схеме, поэтому после перезагрузки страницы их
  видно только после следующего прогона — цена прогонов всегда показана заранее).
- **Хранение:** `AeoCheck.sentiment/sentimentScore/sentimentNote`. Тумблер автопроценки
  хранится в `InstanceSetting` под ключом `aeoSentAuto:<siteId>` (колонки на `Site` в этой
  волне для него нет; миграция при появлении колонки — один UPDATE).

## Доля голоса

Отвечает на вопрос, который AEO-трекер сам по себе не отвечает: **как часто ИИ называет вас, а
как часто — конкурентов.**

Главный принцип: доля голоса и рейтинг цитируемых доменов — **чистая агрегация уже
сохранённых ответов** (`AeoCheck.answerText` + `AeoCheck.citations`, трекер заполняет их с
самого начала). Ни один запрос к ИИ здесь не выполняется. Добавили конкурента — вся история
пересчиталась мгновенно и бесплатно (это видно и по журналу провайдеров в Settings).

Как считаются доли:

1. Для каждой пары (вопрос, движок) в окне 7/30/90 дней берётся **один последний** ответ —
   иначе вопрос, проверенный 30 раз, весил бы в 30 раз больше проверенного один раз. Ответы с
   ошибкой и без текста не участвуют.
2. **Упомянут ли бренд в ответе** — по границе слова, без регистра и диакритики (ёж/ё, ά/α
   сворачиваются), по брендовым словам сайта для «нас» и по «название + другие написания +
   домен» для каждого конкурента. Домен, названный в тексте без ссылки, тоже считается
   упоминанием.
3. **Доля голоса** = упоминания бренда / сумма упоминаний всех брендов. Если не упомянут
   никто — это «нет данных», а не 0 %.
4. **Доля цитирований** — то же по списку цитат: домен принадлежит вам при совпадении с хостом
   по границе точки (`blog.example.com` — ваш, `notexample.com` — нет), конкуренту — по его
   домену.
5. **По движкам** — ответов / упомянуты / процитированы / средняя позиция среди цитируемых /
   лучший конкурент. **Динамика** — доля «нас» по ISO-неделям.

Ниже — **«Источники, которые ИИ цитирует по вашим вопросам»**: какие домены движки цитируют
чаще всего по вашим вопросам, с пометками своих и конкурентов. Попасть в ответы ИИ проще всего
через упоминание на этих сайтах — поэтому у каждой строки кнопка «В Outreach» (локальная
запись, тот же сервис, что и MCP `save_outreach_prospect`; никакого письма не отправляется).

Конкурентов — до 10, домен нормализуется (без схемы, `www.` и пути). Список хранится в
`Site.aeoCompetitors`. MCP: инструмент `get_ai_share_of_voice` (local) отдаёт тот же отчёт.

## Упоминания

Вкладка «Видимость» → «Упоминания» показывает, где о бренде пишут вне вашего сайта, и находит самые дешёвые ссылки для Outreach.

### Источники (бесплатные, без ключей)

- **Google News** — RSS-поиск по каждому брендовому слову как точной фразе, окно 7 дней. Издательство отрезается от заголовка, когда совпадает с полем `<source>`.
- **Википедия** — в языке сайта и в английской секции: статьи, где бренд упоминается, и **внешние ссылки на ваш домен** (`exturlusage`) — второе обычно ценнее: это готовый список страниц, которые уже ссылаются на вас.
- **Wikidata** — сущность бренда со свойством «официальный сайт». Правка сущности всплывает новой строкой: в ключе строки хранится `lastrevid` ревизии.

### Как часто

Планировщик проверяет раз в час, каждый сайт — не чаще раза в сутки (по одному сайту на владельца за тик, чтобы не очередями бить по источникам). Кнопка «Проверить сейчас» запускает внеочередной прогон. Между запросами к Google News выдерживается пауза не менее 2 секунд.

### Что такое mustInclude

«Golden Crown» без контекста притянет короны, отели и конкурсов. У каждого терма есть поле «…и одно из» — список контекстных слов: совпадение считается только когда в заголовке или сниппете есть и терм (по границе слова, без учёта регистра и диакритики), и хотя бы одно контекстное слово. Если термы не заданы, они выводятся автоматически из брендовых слов сайта (Настройки сайта) и имени домена. Прошедшие фильтр результаты сохраняются, остальные отбрасываются до записи в базу.

### Почему ссылки Google News не раскрываются автоматически

Google News отдаёт не адрес статьи, а свой редирект `news.google.com/rss/articles/…`. Раскрытие — это дополнительный запрос к Google на каждое упоминание при каждом прогоне: лишний трафик, который читается как бот и грозит баном. Поэтому редирект хранится как есть, а кнопка «Проверить ссылку» раскрывает адрес и ищет в статье ссылку на ваш домен — только по действию пользователя, один раз. Результат: «есть ссылка», «ссылки нет — повод для outreach» или «страница недоступна». Упоминание без ссылки — самая дешёвая цель для линкбилдинга: о вас уже написали, осталось попросить ссылку (кнопка «В Outreach»).

## LLM Mentions (индекс)

DataForSEO-индекс того, что LLM отвечают по вашим запросам — второй, независимый источник
рядом с живыми проверками: таблица выше — сегодняшние ответы на выбранные вами вопросы, это
индекс того, что модели отвечают вообще, включая вопросы, которые вы не задумались отслеживать.
Тратит ключ DataForSEO, поэтому в share-виде скрыта.

## Стоимость — сводка

| Действие | Цена |
|---|---|
| Доля голоса, цитируемые домены, идеи вопросов, ваша колонка тональности | бесплатно · локальная агрегация сохранённых данных |
| Проверка AEO (любой движок, включая Gemini) | платно · ваш ключ (подтверждение перед запуском) |
| Проверка AI Overviews | платно · ключ DataForSEO (тариф SERP Advanced) или трафик вашего A-Parser |
| Оценка тональности (кнопка или авто) | платно · ≈1 LLM-вызов на ответ, ваш AI-провайдер (цена до запуска) |
| Упоминания (новости/Википедия) | бесплатно · открытые источники |
| LLM Mentions | платно · ключ DataForSEO |

Если схемы базы не хватает (нет колонок `aeoCompetitors` или `sentiment` до
`npx prisma db push`), API отвечает `{ notMigrated: true }`, а не 500.
