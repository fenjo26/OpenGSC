# Footprints & hreflang generator (N1)

Две части задачи N1 волны «Ноябрь»: отчёт «отпечатки сетки» с защитой в генераторе и генератор hreflang-разметки.

## A. Отпечатки сетки — `/footprint`

**Проблема.** Один и тот же шаблон title с подставленным названием слота стоит на нескольких
сайтах портфеля («{слот} Démo Gratuite : Jouer Sans Inscription ni Dépôt» — на 4 сайтах). Для
сетки это отпечаток: виден при ручной проверке и связывается алгоритмически.

**Что читает отчёт (только локальные данные, 0 внешних запросов, бесплатно):**

- **Опубликованное** — последний завершённый `SiteAudit` каждого неархивного сайта:
  `SiteAuditPage.title` и `metaDescription`. H1 в базе аудита нет (только `h1Count`), поэтому
  H1 берётся только из сгенерированного.
- **Сгенерированное** — `SeoHistory` типов `outline` и `text` за 180 дней (не более 400 новых
  записей): `meta.title_options[0]`, `description_options[0]`, `h1` аутлайна; из текста — блок
  меты (`readMetaBlock`) и первая строка `# …`. Так шаблон ловится до публикации.

**Скелет** (`src/lib/footprint/skeleton.ts`, чистые функции): fold без диакритики → сущности
(метка домена без TLD с дефисами→пробелы + `Site.brandedKeywords`; для истории — `keyword`) по
границе слова → `{x}`, длинные первыми → годы 2000–2099 → `{y}` → прочие числа → `{n}` →
схлопывание пробелов. Скелет без `{x}` — совпадение даже без названия сайта — помечается
`noEntity` и участвует в отчёте (это более сильный отпечаток). В отчёт идут группы с числом
сайтов ≥ `minSites` (по умолчанию 2) и скелетом ≥ 4 слов; «одна фраза много раз на одном сайте»
отпечатком не считается. Скелеты, не попавшие в точные группы, собираются в секцию «похожие»
(Jaccard по словам ≥ 0.85, `{x}` не считается; объединение транзитивное, union-find).

**API:** `GET /api/footprint?kind=title|h1|description&minSites=&includeIgnored=&publishedOnly=`
(read) и `POST /api/footprint/ignore` (act) — «нормально, скрыть»; скелет уходит в
`User.footprintIgnore` (JSON-массив) и исчезает из отчёта; `ignored:false` возвращает обратно.
Кнопка/переключатель «показать скрытые» на странице показывает скрытые строки приглушённо.

**MCP:** `get_footprints` (local) — `kind`, `min_sites`, `include_ignored`.

## A'. Защита в генераторе

`genOutline` (после блока META FIT): скелеты `title_options`/`description_options` с сущностью =
`keyword` сверяются с набором «занятых» скелетов портфеля (опубликованное + история ДРУГИХ
ключей, без `footprintIgnore`; кэш в памяти на 1 час, инвалидируется при изменении ignore-листа).
Свободные варианты переставляются вперёд. Если заняты все варианты поля — один вызов `fetchLLM`
«перепиши, не используя эти конструкции: …» (в промпт идут скелеты-конструкции, не чужие title),
3 варианта, проверка кодом: скелет свободен + `fitMetaLocal` в полосе. Не вышло — варианты
остаются, к аутлайну добавляется concern `footprint: <field> reuses a portfolio template`
(поле `_footprint` в объекте аутлайна). Нет данных в портфеле — блок выключен. В `prompts.ts`
(блок МЕТА-ТЕГИ) добавлена одна строка против шаблонных хвостов — без перечисления чужих
шаблонов.

Владелец портфеля для защиты определяется через `workspaceOwner()` — генератор работает и из
фоновых задач, и из MCP, где нет контекста запроса.

## B. Генератор hreflang — `/seo-tools/hreflang`

Ввод: список строк «URL · язык» или список URL + правила «префикс пути → язык»
(`/en/` → `en`, `/` → fallback `fr`); кнопка-режим «Сгруппировать» собирает альтернативы по
одинаковому хвосту пути (`/demo/` ↔ `/en/demo/` — первый сегмент-язык срезается; распознаются
`en`, `pt-br`, `zh-hant`, но не `blog`). Выбор `x-default` (одна из URL или «—»).

Проверка — функциями октябрьского валидатора `src/lib/audit/hreflang.ts` (импорт, файл не
меняется): коды BCP 47, дубли, абсолютные URL, «один URL — один язык».

Выход, три вкладки с «Копировать»: `<link rel="alternate" hreflang>` для `<head>` каждой
страницы (каждая страница несёт полный набор — взаимность), блок `xhtml:link` для sitemap,
HTTP-заголовок `Link:`. Скачивание sitemap-фрагмента `.xml` (готовый документ с
`xmlns:xhtml`). Одиночные кластеры (один язык) показываются отдельным счётчиком.

**«Проверить на сайте»** — `POST /seo-tools/hreflang/verify` (act, подпись net на странице): до
50 URL через `safeFetch`, текущие аннотации читаются из `<head>` и заголовка `Link`
(парсеры валидатора), сравниваются с планом (`diffHreflangPage`): «совпадает» или «отличается»
с постраничным diff (− ожидается, + лишнее). Недоступная страница — не вердикт, а статус.

## Тесты

- `src/lib/footprint/skeleton.test.ts` — 24 теста: 4 продовых title → один скелет (оба реальных
  шаблона), сущность из дефисного домена, приоритет длинной сущности, границы слова, годы/числа,
  `noEntity`, отсечение коротких, группировка по сайтам vs. внутри одного сайта, minSites,
  source=both, сортировка, Jaccard-похожие (включая «`{x}` не считается словом»).
- `src/lib/hreflang/index.test.ts` — 17 тестов: срез языкового сегмента, хвост с query,
  группировка `/` ↔ `/en/`, одиночки, невалидные коды/URL, один URL под двумя языками,
  префикс-правила с fallback, x-default, три формата вывода (точные строки), плохой x-default,
  live-diff (совпадение без учёта порядка/www/слэша, missing, extra).
