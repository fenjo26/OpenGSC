# Trend Radar

В гемблинге (и не только) трафик приходит волнами: вышел новый слот, провайдер выпустил релиз,
в стране поменяли закон. Кто первым написал страницу под запрос — тот и собрал показы.
Trend radar ловит эти волны двумя бесплатными источниками, которых нет ни у одного платного
API трендов: ваш собственный Search Console (реальные показы) и подсказки Google (что начинают
набирать).

**Стоимость: бесплатно — GSC (квота Google) и публичный эндпоинт подсказок.**

## Где находится

Меню **SEO Tools → Demand** — блок «Trend radar» над подбором запросов по рынку. Для каждого
сайта портфеля свой радар (селектор в шапке блока). MCP-инструмент — `get_trends` (local,
только чтение того, что уже собрано).

## Три источника

| Источник | Что ловит | Условие | Score |
|---|---|---|---|
| **Растёт в GSC** (`gsc_rising`) | запрос поднялся против своей же нормы | ≥ 30 показов за 7 дней и рост ≥ ×2 против среднего 7-дневного окна предыдущих 28 дней | `log2(рост) × log10(показы)` |
| **Новое в GSC** (`gsc_new`) | запроса вообще не было, и он появился | ≥ 10 показов за 7 дней, не было ни одного показа за предыдущие 60 дней | `log10(показы)` |
| **Подсказки Google** (`suggest`) | по сидам оператора («slot», «pragmatic play», «taxi thessaloniki») | новое в подсказках = 1 балл; каждый прогон, где повторяется, +0.5 до 3 | 1 → 3 |

Score — «горячесть» источника, у каждого своя шкала; сортировка радара — по нему.

### Задержка данных GSC

Search Console публикует данные с задержкой 2–3 дня, поэтому окно «последние 7 дней»
заканчивается **на последней дате с данными** (она берётся из локального синка DailyMetric),
а не на сегодня. Сравнение полной недели с неполной — гарантированный ложный «рост».

Отсюда же важное: **gsc_rising/gsc_new читают Search Console API напрямую** (3 запроса
`searchanalytics.query` на сайт в сутки), а не DailyMetric. В DailyMetric поисковые строки
хранятся одним 90-дневным агрегатом с датой синка (шаг 4 в `gscSync.ts`) — сравнить «7 дней
против 28» по локальной таблице невозможно конструктивно, это тот же подводный камень, что
задокументирован в `/api/gsc/decay/position`.

### Подсказки: пауза, бюджет, «недоступно сегодня»

- Эндпоинт `suggestqueries.google.com/complete/search?client=firefox`, язык/страна — рынок
  сайта (или свои у сида).
- Пауза ≥ 1 с между запросами; ≤ **50 запросов на сайт за прогон**. Кнопка «Глубоко (a–z)»
  добавляет алфавитное расширение (`seed a` … `seed z`, `seed 0` … `seed 9`) — один сид в
  глубоком режиме это 37 запросов, бюджет заканчивается на первом-втором сиде.
- Не-200 или капча → источник помечается «недоступно сегодня» и до следующего дня не
  дёргается — ни планировщиком, ни кнопкой. Ретраев-молотилки нет; состояние живёт в памяти
  процесса (перезапуск = одна лишняя попытка, не больше).

## Прогон и хранение

Планировщик (`src/lib/trends/scheduler.ts`, стартует из `instrumentation.ts`) гоняет все три
источника **раз в сутки на сайт**: сайты с хоть одним сидом или с GSC-данными в локальном
сторе, до 3 сайтов на владельца и 8 на тик — портфель размазывается на часы, а не одним залпом.

Результат — строки `TrendItem` (уникальность `siteId, source, query`): повторные появления
обновляют score и `lastSeenAt`, новые создаются с `firstSeenAt`. Строка, чей источник молчит
**14 дней**, скрывается из радара (не удаляется — история первого появления сохраняется).
Скрытые вручную (`dismissed`) не возвращаются, пока оператор их не вернёт.

Уведомление (`📈 {site}: растущие запросы`, событие `trend`) — раз в сутки, только о новых
строках со score выше порога (2.0), не больше 8 строк, дедуп через `AlertEvent`
(`trends:<siteId>:<день>`). Первый прогон по сайту молчит — это бэкфилл, а не новость.

## Дайджест

В дайджесте — секция «Растущие запросы» (`digestTrends`): 5 самых горячих запросов портфеля
за период дайджеста (`lastSeenAt` внутри окна), с сайтом и множителем роста. Нет трендов или
таблиц — секции нет.

## Действия в UI

- **Скрыть** — убрать строку из радара (PATCH `/api/trends`).
- **Отслеживать позицию** — добавить запрос в Rank Tracker существующим API
  (`POST /api/rank/keywords`); повторное нажатие — no-op (уникальность ключа).
- **Сделать аутлайн** — открыть `/seo-tools/outline` с ключом в поле сида (тот же
  sessionStorage-механизм передачи, что у Cluster).

## API

| Метод и путь | Право | Что делает |
|---|---|---|
| `GET /api/trends?siteId=&source=&limit=` | read | строки радара + сиды + `suggestUnavailableToday` |
| `PATCH /api/trends { siteId, ids[], dismissed }` | act | скрыть/вернуть строки |
| `POST /api/trends/run { siteId, sources?, deep? }` | act | прогон (бесплатно: квота GSC + подсказки) |
| `GET /api/trends/seeds?siteId=` | read | сиды сайта |
| `POST /api/trends/seeds { siteId, seed, lang?, country? }` | act | добавить сид (≤ 20 на сайт) |
| `DELETE /api/trends/seeds { siteId, seed }` | act | удалить сид |

Таблиц `TrendSeed`/`TrendItem` нет (инстанс подтянул код, но не сделал `db push`) — маршруты
отвечают `{ notMigrated: true }`, UI показывает подсказку про `npx prisma db push`.
